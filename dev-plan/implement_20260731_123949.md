## 개발 목적

Alpine Linux 사용자 공간을 포함하는 Android 앱에서 LLM을 호출할 때 OAuth access/refresh token을 Alpine에 노출하지 않고 Android Host에서 관리하도록 독립 모듈을 완성한다. 기존 Python CLI와 Android runtime 초안을 실제 Android Library 구조로 정리하고, OAuth 인증 결과를 Host LLM Provider 실행 경로에 연결한다.

## 개발 범위

- 현재 `android/*.kt` 소스를 독립 Android Library 모듈 구조로 정리한다.
- OAuth 2.0 Authorization Code + PKCE, callback, 암호화 저장, refresh 경로를 유지·보강한다.
- Alpine client가 Android Host에 요청할 수 있는 loopback Host Bridge를 구현한다.
- Host Bridge는 임시 session token으로 Alpine 요청을 인증하고 OAuth token은 Host 내부에서만 Provider에 전달한다.
- Python `llmctl`이 Host Bridge endpoint와 session token을 사용할 수 있도록 한다.
- Runtime이 Host Bridge endpoint를 Alpine 명령 환경에 주입할 수 있도록 한다.
- Provider별 비표준 OAuth를 추가할 수 있는 경계와 후속 우선순위를 문서화한다.

## 제외 범위

- 실제 OAuth client id/client secret 발급 및 외부 Provider 계정 설정
- 실제 Alpine rootfs 및 PRoot 바이너리 배포
- Kimi Device Authorization Grant 전체 구현
- xAI OIDC discovery 전체 구현
- OpenAI Codex/Claude/Gemini의 비공개 또는 변경 가능한 endpoint를 코드에 고정
- 앱 UI 및 계정 설정 화면
- Play Store 배포

## 최종 결과

- Android Library는 Gradle wrapper를 포함하며 `android-debug.aar` 생성까지 성공했다.
- Android unit test 24건이 모두 통과했고 Android lint는 `No issues found`다.
- Python unit test는 13건 통과, sandbox socket bind 제한 1건 skip이며 compileall/CLI smoke test가 통과했다.
- OAuth Provider token은 Android Keystore 저장소와 Host HTTPS transport 안에만 존재하고 Alpine에는 임시 loopback session token만 전달된다.
- 실제 Provider별 client registration, rootfs/PRoot binary, 실제 기기 end-to-end는 배포 전 외부 준비가 필요한 남은 항목이다.
