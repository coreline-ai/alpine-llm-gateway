# implement_20260809_082423.md

작성 일시: `2026-08-09 08:24:23 KST`

이 문서는 PRoot guest 동적 terminal resize의 production blocker를 우회 없이 다시 해결하기 위한
작업 문서다. 현재 `ProcessBuilder + setsid + slave redirect` topology를 POSIX `forkpty()` 기반의
직접 PRoot exec 구조로 교체해, kernel이 실제 controlling terminal과 foreground process group을
일관되게 소유하도록 한다.

## 개발 목적

PRoot guest에서 `TIOCSWINSZ`가 물리 controlling PTY에 적용될 때 foreground process group으로
`SIGWINCH`가 전달되고 interactive input이 계속 동작하는지 검증 가능한 source-level terminal
architecture를 제공한다.

## 개발 범위

- `alpine-runtime-android` JNI에 API 26+ bionic `forkpty()` 기반 직접 exec 함수를 추가한다.
- Android Kotlin launcher가 검증된 fixed argv/environment로 PRoot를 spawn하고, native child PID의
  wait/terminate lifecycle을 Runtime session에 연결한다.
- production terminal이 실제 acceptance 전까지 `INITIAL_SIZE_ONLY`를 계속 광고하도록 하며,
  검증 성공 시에만 `DYNAMIC` 승격을 고려한다.
- Kotlin unit·Android build와 Samsung의 `stty`, foreground `SIGWINCH`, 반복/storm, input continuity,
  terminal close orphan matrix를 실행한다.

## 제외 범위

- PID/fd reopen, 직접 guest `SIGWINCH` 주입, polling/FIFO, command replay/retry 같은 resize 우회
- Probe-only relay/memfd artifact를 product path로 승격
- PRoot upstream source의 비검증 동작 변경 또는 OpenMinis 코드 복사
- 실제 Provider, Doze/reboot, Play, x86_64 emulator, 공개 release gate

## 2026-08-09 후속: PTY 크기 hint 재주입 차단

직접 `forkpty()` 경로가 host environment를 만들 때 caller environment를 병합한 뒤에도, command 또는
terminal request의 `COLUMNS`/`LINES`가 stale launch-time size hint로 복구될 수 있는지 다시 점검했다.
두 키는 커널 PTY와 `RuntimeTerminalRequest`가 소유해야 하므로 다음을 적용했다.

- [x] `COLUMNS`와 `LINES`를 Runtime reserved environment로 지정했다. session, command, terminal request
  중 어느 경로로도 주입하면 `INVALID_REQUEST`로 fail-closed 처리한다.
- [x] `hostEnvironment()`는 caller environment 병합 뒤 두 키를 다시 제거해 validation bypass가 생겨도
  stale hint가 child `execve`로 전달되지 않도록 defense-in-depth를 유지한다.
- [x] Kotlin unit test는 terminal request·session environment·command request의 두 key 모두를 검증했고,
  `:alpine-runtime-android:testDebugUnitTest`, `:alpine-runtime-android:assembleDebug`,
  `:integrated-app:assembleDebug`가 통과했다.
- [x] Python module-boundary static test(23/23)는 reserved key와 remove ordering을 확인한다.

이 변경은 request validation과 launcher environment 구성만 다루므로, Samsung PRoot `SIGWINCH` blocker나
production `INITIAL_SIZE_ONLY` contract를 변경하지 않는다. 해당 physical acceptance는 위 Phase 3의
`BLOCKED` 상태를 유지한다.
