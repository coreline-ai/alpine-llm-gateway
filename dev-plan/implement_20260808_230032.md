# Phase 1c: PRoot signal-injection isolation Probe

작성 일시: `2026-08-08 23:00:32 KST`

## 목적

`tty-resize-relay16`은 supervisor → direct PRoot → primary tracee의 `SIGWINCH` 전달과 shell trap을
확인했지만, signal 직후 고정 `printf` command도 재개되지 않았다. 이어서 `relay17-no-forward`는
PRoot의 direct-primary-tracee injection을 제거했는데도 Samsung에서 tracee `SIGWINCH` stop/restart 1회와
입력 중단을 관찰했다. `relay18-sigwinch-blocked`는 guest tracee stop/restart를 0회로 만들었지만 input은
여전히 재개되지 않았다. 즉 단순 host-side relay 제거·guest mask가 해법이 아님이 확인되었다.

`relay19` 이후 `relay20`은 PRoot source에서 initial tracee group과 physical tty foreground group이 실제로
일치하는지 확인했고, `relay21`은 same-PTY `TIOCGWINSZ`를 호출한 **active guest tracee**도 그 foreground
group에 속하는지 fixed stage만으로 추가 확인한다. 별도 host-only PTY control은 Android PTY에서
`TIOCSWINSZ → SIGWINCH → 이후 input`이 정상임을 PRoot 없이 검증한다.

1. `TIOCSWINSZ`/same-PTY winsize 자체가 terminal input을 막는지
2. direct primary-tracee signal injection과 PRoot ptrace reinjection이 terminal input을 막는지

## 범위 및 금지 사항

- Probe 전용 PRoot artifact만 변경한다. production `libproot.so`, Runtime API/UI capability와 package는
  변경하지 않는다.
- `/proc` PID lookup, guest FIFO/polling, host foreground-group broadcast, terminal payload logging을
  추가하지 않는다.
- fixed literal diagnostic stage·bounded marker만 사용한다. prompt, command, PID, credential은 결과에
  저장하지 않는다.
- dynamic resize가 signal 없이 size marker만 통과해도 제품 `DYNAMIC` 승격은 금지한다.

  relay하지 않도록 한다. **결과:** no-forward 상태에서도 tracee stop/restart 1회와 입력 중단이 발생했다.

## 완료 기준

- 모든 결과는 Probe-only evidence로 기록한다.
- `GUEST_SIGWINCH_REPEAT_STRESS_UNSUPPORTED` blocker를 실제 결과와 일치시킨다.
- production terminal은 결과와 무관하게 기존 fail-closed public contract를 유지한다.
- `relay21` 결론: Samsung에서 host control PASS, active tracee physical foreground PASS, PRoot resize input
  recovery FAIL이다. 따라서 `GUEST_SIGWINCH_REPEAT_STRESS_UNSUPPORTED`를 유지하며 current Probe artifact는
  release candidate가 아니다.

## 2026-08-09 Relay24 virtual-winsize memfd control

- [x] `relay24-virtual-winsize-memfd` Probe-only artifact를 추가했다. Host bridge는 bounded 5-byte request만
  private supervisor에 전달하고, supervisor는 direct PRoot에만 상속된 4-byte memfd에 dimensions를 저장한다.
  host-master `TIOCSWINSZ`, post-launch host/guest signal, guest PID lookup, FIFO/polling, terminal payload
  logging은 사용하지 않는다.
- [x] PRoot는 guest `TIOCGWINSZ` 성공 exit에서만 memfd를 read하여 result를 바꾸도록 했다. artifact digest,
  lock, Gradle checksum, boundary regression을 갱신했다. 이 artifact는 Probe에만 포함되며 product pack/API는
  계속 `INITIAL_SIZE_ONLY`다.
- [x] Samsung single regression: supervisor store와 PRoot memfd-ready fixed stage는 확인했지만,
  `virtual_winsize_read_applied=0`, dynamic `stty` marker/helper/follow-up input은 미응답이었다.
- [x] memfd write 자체를 분리하기 위한 explicit Probe-only **no-write negative control**을 추가했다. 동일한
  bounded private socket 요청을 supervisor가 validate/ack만 하고 memfd write를 생략한 Samsung 재현에서도
  no-write stage `1`, guest signal stop/restart `0/0`, 이후 fixed marker/helper/follow-up input 미응답이었다.
  따라서 현 failure는 memfd write/read 또는 `SIGWINCH`만으로 설명되지 않으며, private resize-request
  transaction/supervisor session path까지 포함한 PRoot terminal interaction을 추가로 분리해야 한다.
- [x] 후속 Samsung source-isolation control에서 resize API 호출·socket/memfd request·foreground assignment를
  각각 생략해도 input failure가 남음을 확인했다. 기본(unpatched) PRoot는 `TIOCGWINSZ`를 전부 생략한 경우
  여러 독립 fixed input batch와 follow-up이 통과했지만, initial `stty size` 뒤 별도 input batch는 재개되지
  않았다. patched relay24에서도 read를 피한 pre-buffered 흐름은 통과했고 seccomp-off control은 failure를
  바꾸지 못했다. Android ioctl seccomp filter를 source-level로 완전히 제거한 relay25 control도 실패했다.
  현재 blocker는 PRoot terminal의 post-`TIOCGWINSZ` input lifecycle이며 user input replay는 허용하지 않는다.

### Relay24 판정

- Probe evidence는 강화됐지만 dynamic resize 해결은 **실패**다.
- production contract와 release blocker `GUEST_SIGWINCH_REPEAT_STRESS_UNSUPPORTED`는 변경하지 않는다.
- 다음 후보는 PRoot process와 terminal session supervisor를 분리하지 않는 maintained/upstream terminal
  architecture 또는 PRoot 밖의 alternative terminal backend다. no-write control을 product workaround로
  승격하지 않는다.

### Relay29·Relay30 해석 보정 (2026-08-09)

후속 source-level recorder는 기존 `size="$(stty size)"` marker가 second guest `TIOCGWINSZ` enter와 success
exit에 도달함을 확인했다. target의 stdout write와 exit도 non-empty/success였지만, 이 stdout은 command-substitution
pipe로 갈 수 있으므로 marker 미응답만으로 PRoot/PTY post-get input failure를 주장할 수 없다. 같은 조건의 direct
fixed guest helper는 stdout write·exit과 terminal response를 모두 보였다. 그러므로 위의 broad post-`TIOCGWINSZ`
input-stall 해석은 historical investigation evidence로만 남기며, 현재 dynamic resize blocker는 **actual resize
update와 SIGWINCH/repeat/storm/TUI/orphan matrix의 미증명**이다. 세부는 `implement_20260809_064200.md`를 따른다.
