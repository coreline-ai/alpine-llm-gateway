# implement_20260808_093115.md

작성 일시: `2026-08-08 09:31:15 KST`

이 문서는 Android 직접 Provider OAuth 도중 Activity 재생성·process death·강제 종료가 발생했을 때 안전하게 복구하는 작업 범위를 고정한다.

## 개발 목적

- OAuth 브라우저가 열린 상태에서 Host Activity 또는 app process가 종료되어도 다음 실행이 무한 진행 상태나 잘못된 로그인 완료 상태가 되지 않게 한다.
- 중단된 Authorization Code + PKCE transaction을 자동 재실행하지 않고 폐기한 뒤 사용자가 명시적으로 새 로그인을 시작하게 한다.
- 이전 callback과 중복 action이 새 인증 시도나 다른 Provider profile에 영향을 주지 않게 한다.
- token·authorization code·PKCE verifier·state·Provider 원문을 UI, 일반 preference, 로그와 테스트 증거에 노출하지 않는다.

## 개발 범위

- Provider profile별 비밀정보 없는 OAuth 시도 lifecycle marker와 원자적 상태 전이
- 정상 완료·실패·명시적 취소·Activity 재생성·process death의 종료 정책 분리
- 앱 재진입 시 orphaned encrypted transaction 폐기, 중단/만료 안내와 명시적 재로그인
- stale callback의 in-process allowlist 거부와 새 시도 중복 방지 회귀
- fake Provider 기반 단위·instrumentation과 Samsung `SM-S931N` lifecycle 검증
- README, Provider OAuth 문서와 상위 개발 계획의 완료/잔여 gate 동기화

## 제외 범위

- 실제 Provider 계정, OAuth public client registration, 실제 token endpoint 호출
- 중단된 PKCE transaction 또는 브라우저 callback의 자동 resume
- token·PKCE verifier·state를 일반 SharedPreferences에 복제
- Samsung 재부팅·Doze·배터리 제한 전체 suite
- Provider 정책 승인, signed Play 배포와 x86_64 device matrix
- MobileAgent Flutter OIDC/BFF 인증 경로 변경

## Phase 1. lifecycle 위협·복구 계약 확정

### 목표

### 구현 태스크

- [x] `OAuthManager`가 PKCE transaction은 암호화 저장하지만 callback server·registry·coroutine은 process-local임을 확인한다.
- [x] `ProviderProfilesActivity.onDestroy()`가 진행 중 인증을 취소하며 재생성/강제 종료 복구 상태는 저장하지 않음을 확인한다.
- [x] process death 뒤 encrypted transaction이 남고 callback server·registry는 사라져 자동 resume가 불가능함을 확인한다.
- [x] 복구 정책을 `IN_PROGRESS → INTERRUPTED/EXPIRED → 사용자 명시적 재로그인`으로 확정한다.
- [x] 성공 token이 존재하면 marker와 orphan transaction만 정리하고 인증 상태를 유지하기로 확정한다.

- [x] lifecycle marker가 OAuth state·verifier·code·token을 포함하지 않는 계약을 확정한다.

## 구현 결과

- `ProviderAuthorizationRecoveryStore`가 profile/attempt ID, `IN_PROGRESS`·`INTERRUPTED`와 시작 시각만 동기 저장한다.
- 정상 성공·실패·명시적 취소는 matching attempt만 정리하며 Activity/system destruction은 중단 상태로 남긴다.
- 다음 Provider 화면은 orphaned encrypted OAuth transaction을 폐기하고 `AUTH_FLOW_INTERRUPTED` 또는 `AUTH_SESSION_EXPIRED`만 표시한다.
- token 저장까지 성공한 profile은 stale marker와 transaction만 정리하고 token·연결 상태를 유지한다.
- Android OAuth instrumentation 3/3, Provider instrumentation 12/12, 신규 Demo lifecycle 3/3, Demo 전체 37/37와 Integrated 10/10이 Samsung `SM-S931N`에서 통과했다.
- credential-free persisted `IN_PROGRESS` fixture를 실제 `am force-stop`·cold start한 뒤 redacted 중단 안내와 명시적 로그인 action을 확인했다.
- Android/Provider/Chat unit, Android/Provider/Demo/Integrated Lint, 통합 APK·Test APK build가 통과했다.

## 잔여 리스크 / 후속 과제

- 실제 Provider 계정과 browser callback이 진행 중인 순간의 process kill은 앱 소유 client registration과 계정 owner 승인 창에서 별도 수행해야 한다.
- 실제 refresh token rotation 직후 종료, logout/revoke, OEM background 제한, reboot·Doze는 아직 완료되지 않았다.
- x86_64 emulator와 iOS MobileAgent process lifecycle은 별도 device matrix다.
