## 개발 목적

연결된 Samsung `SM-S931N` Android 실기기에서 Alpine LLM Gateway의 기존 instrumentation test를 실행하고, JVM 테스트만으로 확인할 수 없었던 Android Keystore, 실제 loopback socket, 기기 ABI 선택, 샘플 앱 설치·실행 경계를 검증한다. 실기기에서 발견되는 구현 결함은 재현 테스트와 함께 수정한다.

## 개발 범위

- 대상 Samsung 기기의 Android API, ABI, 보안 패치와 저장 공간 정보를 기록한다.
- 기존 OAuth token store와 runtime asset selector instrumentation test를 실기기에서 실행한다.
- Android Keystore 저장 데이터에 OAuth token 평문이 남지 않는지 검증한다.
- 실제 기기 loopback에서 Host Bridge 인증, completion, streaming과 종료 후 port 반환을 검증한다.
- 실제 기기 ABI가 production runtime asset selector와 일치하는지 검증한다.
- sample debug APK를 설치·실행하고 crash 및 credential 로그 노출을 점검한다.
- 발견된 코드 또는 테스트 결함을 수정하고 Android/Python 회귀 테스트를 실행한다.

## 제외 범위

- 실제 Provider client registration과 사용자 계정을 필요로 하는 OAuth 로그인
- 실제 Provider API 과금 요청
- 저장소에 포함되지 않은 PRoot 바이너리와 Alpine rootfs의 다운로드·재배포
- 실제 PRoot/Alpine command 실행
- Google Android OAuth redirect 전략 변경
- CI workflow와 외부 artifact publication

## 잔여 리스크 / 후속 과제

1. Provider client registration과 credential이 없어 실제 Gemini/Claude OAuth 및 API E2E는 수행하지 않았다.
2. PRoot/rootfs asset이 저장소와 sample APK에 없어 실제 Alpine 설치와 `llmctl` 실행은 수행하지 않았다.
3. 현재 OAuth callback은 loopback 방식이므로 Google Android OAuth 등록 정책과의 실호환성 검증 및 App Link/custom scheme 전략이 필요하다.
