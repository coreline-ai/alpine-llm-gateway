# implement_20260801_075228.md

작성 일시: `2026-08-01 07:52:28 KST`

이 문서는 현재 Android LLM 채팅 앱에 권장 기본 스킬과 기본 응답 페르소나를 추가하는 범위를 고정하고, 구현이 Alpine 실행형 agent나 확장 marketplace 범위로 확대되지 않도록 하기 위한 작업 문서다.

## 개발 목적

사용자가 Provider·모델과 별개로 **무엇을 잘할지 선택하는 기본 스킬**과 **어떤 방식으로 답할지 선택하는 응답 페르소나**를 대화별로 설정할 수 있게 한다. 앱 기본값을 지정하면 새 대화가 해당 설정을 상속하고, 전송 시 선택된 설정을 bounded system instruction으로 조합해 Anthropic, Gemini, Codex, OpenAI-compatible, xAI 요청에 동일한 의미로 전달한다.

## 개발 범위

- 내장 기본 스킬 8개와 응답 페르소나 7개를 정적 catalog로 제공한다.
- 한 대화에는 기본 스킬 1개와 페르소나 1개만 선택한다.
- 앱 기본값은 `general` 스킬과 `balanced` 페르소나로 시작한다.
- 현재 대화 설정과 새 대화 기본값을 구분해 저장한다.
- 현재 대화의 스킬·페르소나 변경은 생성 중 응답을 바꾸지 않고 다음 전송부터 적용한다.
- 전송 시작 시 선택값과 생성된 system instruction을 고정 캡처한다.
- 재시도는 실패한 요청이 사용한 스킬·페르소나를 그대로 재사용한다.
- 대화·assistant 메시지 metadata에 사용한 스킬·페르소나 ID를 저장하고 앱 재시작 후 복원한다.
- `ChatRequestBuilder`가 bounded top-level `system` 필드를 생성하도록 확장한다.
- 채팅 화면에 현재 Assistant mode를 표시하고 modal bottom sheet에서 스킬·페르소나를 선택한다.
- 기존 암호화 대화 저장소를 schema v1에서 신규 schema로 손실 없이 migration한다.
- Provider adapter 회귀, JVM/Compose instrumentation, lint, APK와 삼성폰 smoke test를 갱신한다.

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.

- 기존 Provider request JSON과 adapter의 top-level `system` 계약을 우선 사용한다.

- system instruction 원문, 대화 내용과 Provider 응답을 log, crash message 또는 test tag에 포함하지 않는다.
- catalog에 없는 ID, 삭제된 ID와 손상 설정은 `general`/`balanced`로 fail-safe fallback한다.
- 전송 중 선택 변경은 시작 당시 요청, metadata, retry target과 background stream을 바꾸지 않는다.

## Prompt 조합 계약

system instruction은 아래 순서를 고정한다.

1. 앱의 고정 응답·안전 경계
2. 선택한 스킬 instruction
3. 선택한 페르소나 instruction

대화 메시지는 기존 user/assistant history로 별도 전달한다. system instruction은 message history에 사용자 메시지처럼 저장하지 않으며, 최대 UTF-8 byte 제한과 제어 문자 정규화를 적용한다.

## 잔여 리스크 / 후속 과제

- Provider별 system instruction 해석 차이로 같은 persona라도 표현 차이가 생길 수 있다.
- system prompt는 응답 성향을 유도하지만 정확성이나 보안 정책 준수를 단독으로 보장하지 않는다.
- 향후 실행형 Alpine skill은 이 계획을 확장하지 않고 장기 계획 Phase 7·10의 별도 권한·audit workstream으로 구현해야 한다.
- custom persona, 외부 skill, 여러 skill 조합에는 prompt injection, 서명, 권한 상승과 migration 정책이 별도로 필요하다.
