# Workspace SAF export 크기 상한 보강 계획

작성 일시: `2026-08-09 12:00:00 KST`

## 목적

`WorkspaceSafTransfer`의 export API는 현재 통합 앱 호출이 이미 bounded read를 수행한다는
전제에 의존한다. 재사용 가능한 Android 모듈의 public API에도 export byte 상한을 강제해,
다른 consumer가 큰 배열을 전달하거나 실수로 호출해도 provider I/O 이전에 fail-closed 되게 한다.

## 범위

- `alpine-workspace-android`의 export API에 명시적 상한과 안전한 기본값을 둔다.
- 상한 초과 또는 잘못된 상한은 destination `content://` I/O 전에
  `WorkspaceErrorCode.LIMIT_EXCEEDED`로 정규화한다.
- `integrated-app`은 실제 workspace read limit을 명시적으로 전달한다.
- Android instrumentation으로 성공 export와 failed export의 대상 보존을 검증한다.

## 제외 범위

- DocumentsUI를 통한 수동 import → 편집 → terminal → export/share 실기기 QA
- 외부 provider의 저장소/네트워크 정책, archive extraction, PRoot terminal resize
- package live repository, Provider 계정, Doze/reboot 및 release gate

## 안전 조건

- URI, 파일 본문, user prompt, credential을 문서나 test result에 기록하지 않는다.
- export는 명시적으로 선택된 destination URI만 열며, size rejection은 URI를 열기 전에 완료한다.
- 기존 consumer 호환성을 위해 2-argument overload는 유지하되 보수적인 기본 상한을 적용한다.
