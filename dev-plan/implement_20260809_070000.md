# Phase 1h: Relay31 virtual winsize + second-get output composite

작성 일시: `2026-08-09 07:00:00 KST`

## 목적

Relay30은 second guest `TIOCGWINSZ`가 성공하고 freestanding helper의 direct stdout도 terminal까지
전달됨을 보였다. `stty` command-substitution marker의 무응답은 일반적인 PTY failure를 증명하지 못한다.
이번 단계는 Relay24의 private four-byte memfd virtual-winsize source patch와 Relay30의 fixed lifecycle
recorder를 하나의 **Probe-only** PRoot artifact로 결합해, 실제 bounded resize request 이후 helper가
`dynamic`을 반환하는지 확인한다.

## 안전 경계

- Relay31은 `:alpine-runtime-probe`에만 들어가는 disposable diagnostic artifact다.
- fixed dimensions와 closed lifecycle enums만 기록한다. prompt, terminal bytes, command, path, PID, fd,
  errno, credential은 기록하지 않는다.
- polling, FIFO, replay/retry, PID/fd reopen, post-launch host/guest signal injection을 추가하지 않는다.
- Relay24의 virtual result replacement가 동작하더라도 `SIGWINCH`, physical PTY update, repeat/storm,
  rotation, TUI, orphan matrix 전에는 product contract를 승격하지 않는다.
- product Runtime은 계속 `INITIAL_SIZE_ONLY` / `TERMINAL_RESIZE_UNSUPPORTED`를 유지한다.

## Samsung arm64 결과

Relay31 seccomp-off control은 실제 bounded virtual resize request 뒤 다음 fixed 결과를 보였다.

| 관찰 | 결과 | 해석 |
|---|---:|---|
| private virtual state store | `1` | supervisor가 bounded request를 memfd에 저장 |
| PRoot virtual fd ready | `1` | direct PRoot process가 private fd를 수용 |
| PRoot virtual result apply | `3` | successful guest get 결과를 source-level state로 대체 |
| second get enter / success | `1 / 1` | direct helper가 요청한 후속 get이 정상 완료 |
| target stdout non-empty exit | `1` | helper의 direct output path가 terminal에 전달 |
| helper fixed result | `dynamic` | helper가 requested virtual dimensions를 관찰 |
| guest `SIGWINCH` | `0` (의도된 no-signal mode) | signal semantics는 미검증 |

Probe result는 `success=true`, `terminal_resize_support=DYNAMIC`이었지만 이는 Relay31 disposable diagnostic
contract에 한정된다. repeat/storm request 수는 `0`이고 rotation, alternate screen TUI, orphan 검증도 하지 않았다.
따라서 제품 Runtime API는 승격하지 않으며 `INITIAL_SIZE_ONLY`/`TERMINAL_RESIZE_UNSUPPORTED`를 유지한다.
