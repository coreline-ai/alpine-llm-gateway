# Provider 401 Refresh Without Inference Replay

작성 일시: `2026-08-09 14:00:00 KST`

## 목적

Provider별 real-time inference idempotency key/header 계약이 `NOT_CONFIRMED`인 상태에서, OAuth access token이
401로 거부되면 `OAuthLlmSession`이 refresh 후 같은 inference POST를 자동 재전송하던 경로를 제거한다.

## 근거

- OpenAI, Anthropic, Gemini, xAI 공식 모델·오류·rate-limit 문서를 2026-08-09에 재확인했다.
- Anthropic 및 Gemini 공식 문서는 transient failure backoff/SDK retry를 설명하지만, 현재 Android adapter가
  사용하는 real-time inference POST의 dedupe key, TTL, conflict semantics를 제공하지 않는다.
- OpenAI/xAI model/request-correlation·batch 식별자 역시 current adapter의 real-time chat/Responses POST
  자동 재전송 계약으로 승격할 수 없다.
- 따라서 `NEVER_AUTOMATIC`을 모든 built-in adapter의 default contract로 유지한다.

## 구현

- [x] `OAuthLlmSession`을 credential source 경계로 분리해 Android Keystore/OAuthManager 없이 정책 회귀를
  단위 검증할 수 있게 했다.
- [x] 401이면 token refresh는 next user action을 위해 수행하되, complete/stream의 원 inference POST는
  재전송하지 않고 최초 401 결과를 반환하도록 변경했다.
- [x] refresh 실패/invalid credential은 `OAuthRequiredException`으로 fail-closed 처리한다.
- [x] OpenAI-compatible(xAI 포함), Anthropic, Gemini, Codex built-in adapter가
  `ProviderRetrySafety.NEVER_AUTOMATIC`과 idempotency header 미설정을 유지하는 회귀를 추가했다.

## 검증

- [x] `:android:testDebugUnitTest` — OAuth 401 stream/complete no-replay, no-refresh reauthentication,

  `:alpine-chat-backend-direct:testDebugUnitTest` — downstream session/backend 회귀 PASS.

## 남은 외부 조건

- 실제 Provider OAuth/API, 정확한 account model catalog, 429·5xx·mid-stream fault 및 endpoint별
  idempotency 계약은 계속 `NOT_RUN`/`NOT_CONFIRMED`다.
- 이 변경은 credential refresh request 자체를 막지 않지만, inference request 재전송과 backend fallback은
  자동으로 수행하지 않는다.
