# Phase 1j: PRoot post-`TIOCGWINSZ` handoff source audit

작성 일시: `2026-08-09 07:13:38 KST`

## 목적

Relay31/32가 증명한 것은 Probe-only private virtual state의 **query-level** 관찰이다. 이는 host PTY의
physical winsize, guest foreground process group의 `SIGWINCH`, interactive terminal/TUI semantics를 해결하지
않는다. 이 단계는 PRoot가 있는 Android PTY에서 guest `TIOCGWINSZ` 이후 interactive input/output이 불안정해지는
source-level 경계를 다시 감사하고, 유지보수 가능한 physical resize 후보만 남기는 데 목적이 있다.

## 비목표·안전 경계

- product Runtime/API의 `INITIAL_SIZE_ONLY`와 `TERMINAL_RESIZE_UNSUPPORTED`를 이 단계에서 변경하지 않는다.
- virtual memfd, Relay artifact, direct PID signal, polling/FIFO, command replay/retry, fd/PID reopen을 제품
  workaround로 사용하지 않는다.
- terminal bytes, guest command, prompt, PID/fd, credential, provider 오류 원문을 report·test assertion·문서에
  저장하지 않는다.
- Probe artifact는 product APK/SDK public API에 포함하지 않는다.
- Samsung reboot, Doze, battery policy, 8-hour soak는 사용자 승인 없이는 수행하지 않는다.

## 구현·검증 체크리스트

- [x] bundled PRoot source와 Relay25~32 patch를 대조해 `TIOCGWINSZ` exit, syscall restart, child wait,
  host PTY ownership 사이의 실제 handoff를 fixed source stages로 모델링했다.
- [x] physical `TIOCSWINSZ`/foreground `SIGWINCH`/terminal bytes를 바꾸지 않는 static source audit을
  선택했다. pinned source에 production으로 승격 가능한 lifecycle hook이 없음을 확인했으므로 추가 Probe는
  만들지 않았다.
- [x] `scripts/verify-proot-terminal-handoff.py`와 회귀 테스트를 추가했다. 이는 source revision, Android
  `PR_ioctl` sysexit trace, generic tracee signal→`ptrace` restart, stock winsize rewrite 부재를 fail-closed로
  확인하며 runtime/API를 변경하지 않는다.
- [x] 새 physical candidate가 없으므로 Samsung resize matrix를 재실행하지 않았다. 기존 Relay31/32는
  query-level evidence로만 유지하고 product 계약을 승격하지 않았다.
- [x] Probe artifact가 product와 분리된 상태를 유지하고 ADR/readiness/GOAL 감사를 실제 결과로 갱신했다.

## 결과

`8cf13e997cdc9472997aae19df8050c073c9a86c` pinned PRoot source에 대한 static audit은 통과했다.
Android `PR_ioctl`은 sysexit trace 대상이고, tracee signal stop은 syscall chain이 아닐 때 generic
`ptrace(..., signal)` restart로 전달될 수 있다. 그러나 stock source는 `TIOCGWINSZ`/`TIOCSWINSZ` 결과를
재작성하거나 `SIGWINCH`를 생성·relay하는 terminal hook을 제공하지 않는다.

따라서 Relay31/32를 production patch로 바꾸거나 새로운 direct signal/session workaround를 추가할 근거는
없다. 현재 source만으로 Android PRoot post-ioctl lifecycle의 정확한 root cause를 안전하게 더 좁힐 수
없으므로, 다음 구현 후보는 upstream/maintained terminal hook 또는 PRoot를 대체하는 controlling-terminal
architecture다. 그 전까지 `INITIAL_SIZE_ONLY`/`TERMINAL_RESIZE_UNSUPPORTED`와
`GUEST_SIGWINCH_REPEAT_STRESS_UNSUPPORTED`를 유지한다.
