# implement_20260731_205557.md

작성 일시: `2026-07-31 20:55:57 KST`

이 문서는 OpenMinis의 Codex OAuth 구현 검토 결과를 Alpine Android 모듈에 안전하게 반영하고, 구현이 타 Provider나 Alpine 완전 통합 범위로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

현재 범용 `OPENAI_COMPATIBLE` OAuth 경로와 분리된 Codex 전용 OAuth/Responses 경로를 추가한다. OpenMinis에서 확인한 Codex 인증·호출 계약은 필요한 부분만 반영하고, Alpine의 엄격한 state 검증, 암호화 fail-closed 저장, refresh single-flight, 응답 제한과 오류 비노출 경계를 유지한다.

## 개발 범위

- OAuth callback host와 fallback port 정책을 Provider별로 설정할 수 있게 한다.
- loopback callback socket에 read timeout과 bounded request/header parsing을 적용한다.
- Codex 전용 OAuth 계약을 추가한다.
  - `localhost:1455/auth/callback`
  - PKCE S256과 엄격한 state 검증
  - JSON authorization-code/refresh token 요청
  - Codex authorization 추가 파라미터
  - ID Token의 account/plan 표시용 metadata 추출
- Codex 전용 Responses API adapter를 추가한다.
  - 고정 HTTPS endpoint와 Codex client header
  - OpenAI 공통 messages/image/function tool 입력을 Responses 입력으로 변환
  - 일반 응답과 SSE text/tool/usage/terminal event를 공통 Host 형식으로 변환
  - account id를 제한된 credential metadata header 경계로 전달
- 데모 앱에 별도 `CODEX` Provider 유형과 고정 계약 profile을 추가한다.
- mock 기반 계약 테스트, Android unit test, assemble, lint와 문서를 갱신한다.

## 제외 범위

## 최종 결과 요약

- Alpine의 PKCE/state/Keystore/refresh single-flight 코어를 유지한 채 Codex 전용 OAuth contract를 추가했다.
- `localhost:1455/auth/callback`과 fallback 비활성 정책을 지원하고 callback parser에 read timeout과 request/header limit을 적용했다.
- Codex token exchange와 refresh는 초기 openminis 비교 구현에서 JSON으로 작성했으나, 실기기 재검토 후 최신 first-party Codex와 같은 form-urlencoded로 교정했다. ID Token 원문 없이 account/plan 표시 claim만 암호화 metadata에 저장한다.
- Codex account token은 고정 `chatgpt.com/backend-api/codex/responses` endpoint에만 전달하며 account id도 credential 주입 경계에서 지정 헤더로 추가한다.
- OpenAI 공통 text/inline image/function tool 입력을 Responses 형식으로 변환하고 non-stream 및 text/tool/usage/terminal SSE를 공통 Host 형식으로 정규화한다.
- 데모에 별도 Codex 유형을 추가하고 endpoint/scope/callback은 읽기 전용·fail-closed로 고정했다. OAuth public client ID는 하드코딩하지 않았다.
- Android Library JVM test 63개와 demo JVM test 27개가 모두 통과했다.
- Android Library/sample/demo debug assemble·lint와 두 instrumentation APK assemble이 통과했다.
- Python 3.11 unittest 49개, compileall, `git diff --check`와 credential/log sentinel 검사가 통과했다.

## 잔여 리스크 / 후속 과제

- 실제 ChatGPT/OpenAI 계정, 앱 소유 public client registration과 고정 redirect 등록을 사용한 E2E는 credential이 없어 수행하지 않았다.
- `chatgpt.com/backend-api/codex/responses`, Codex 전용 header와 기본 client version은 구현 세부 계약이므로 Provider 변경 시 호환성 갱신이 필요하다.
- 실제 계정 사용 가능성과 배포 정책 적합성은 별도 확인이 필요하며 다른 앱/CLI의 public client ID를 복사해서는 안 된다.
- instrumentation test APK는 컴파일했지만 Codex callback intent routing과 실제 브라우저 복귀를 실기기에서 실행하지 않았다.
- Reasoning 원문 노출, 이미지 생성, 오디오와 Fast Mode는 계획 범위에서 제외했다.
