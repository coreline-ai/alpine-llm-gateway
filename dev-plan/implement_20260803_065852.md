# implement_20260803_065852.md

작성 일시: `2026-08-03 06:58:52 KST`

이 문서는 통합 제품 장기 계획의 **Phase 3: Alpine 작업 모드 통합** 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

- `:integrated-app`의 Alpine 작업 모드에서 Alpine Runtime, HostBridge, Python Gateway와 공통 채팅 기능을 실제 하나의 실행 흐름으로 연결한다.
- Android Provider OAuth 자격증명은 Host에만 유지하고 Guest에는 만료되는 capability 파일만 노출한다.
- Alpine 준비 실패 시 Provider dispatch 전 사용자 승인을 받은 경우에만 빠른 채팅 fallback을 허용하며, dispatch 이후에는 자동 재전송하지 않는다.
- 기존 Runtime·Bridge·routing·공통 Chat Feature 모듈을 조립해 다른 Android 앱에서도 재사용 가능한 경계를 유지한다.

## 개발 범위

- Application 단위 Bridge/Gateway lifecycle owner와 Provider session 연결
- Runtime session을 Bridge와 최소 Terminal UI가 안전하게 공유하는 host 계약
- routing backend를 공통 `ChatBackendSession`으로 연결하는 adapter
- Alpine 모드의 채팅/도구 화면, 통합 상태, 시작·상태 검사·재시작·종료·복구 UI
- 명시적 fallback 승인 UI와 runtime 오류별 안전한 복구 action
- JVM, instrumentation, 일반 arm64 실기기와 release·원격 CI 조합 회귀 검증
- Samsung 모델 전용 인증은 연결 가능한 기기와 승인된 시험 창이 필요한 Phase 9 gate로 이관
- Phase 3 검증 문서 및 상위 계획 상태 업데이트

## 제외 범위

- Phase 4의 완성형 ANSI/VT Terminal, 동적 PRoot guest resize와 다중 terminal tab
- Phase 5의 범용 파일 탐색기·편집기·SAF 및 package 검색 catalog
- 실제 Provider 계정 OAuth/API 운영 승인과 의도적 429·5xx 발생 시험
- x86_64 emulator 제품 지원 승인
- 공개 배포 license·Play track·책임자 gate 해소

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.

- 자동 fallback은 금지하고 같은 request를 dispatch 이후 다른 backend로 재전송하지 않는다.

## Phase 3.1. 공통 계약과 Runtime session 공유

### 목표

- 기존 routing backend를 공통 Chat Feature에서 사용할 수 있게 하고 Bridge가 소유한 Runtime session을 host UI가 안전하게 사용할 수 있게 한다.

### 구현 태스크

- [x] routing 결과를 `ChatBackendSession` stream으로 변환하는 재사용 adapter를 추가한다.
- [x] runtime·fallback 실패를 공통 redacted failure/recovery 계약에 추가한다.
- [x] `RuntimeHostController`에 외부 owner session의 명시적 bind/unbind 계약을 추가한다.
- [x] `AlpineLlmBridgeController`가 현재 active Runtime session을 owner 확인 아래 제공한다.
- [x] Android direct backend가 안전한 normalized stream 함수를 받을 수 있게 공개 조립점을 제공한다.

### 자체 테스트

- [x] fallback 거절·runtime 실패·dispatch 이후 실패 mapping이 통과한다.
- [x] 외부 Runtime session bind 해제 시 terminal 참조가 정리되고 Runtime 소유권은 이동하지 않는다.
