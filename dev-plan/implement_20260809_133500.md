# Current GitHub Remote CI Gate Fail-Closed Reconciliation

작성 일시: `2026-08-09 13:35:00 KST`

## 목적

GOAL은 GitHub Push와 원격 CI를 외부 조건으로 분류하며, 실제 current HEAD/worktree에 대응하는
workflow run 증거가 없으면 완료로 취급하지 않도록 요구한다. 기존 readiness는 과거 성공 baseline을
`READY`로 표시했지만, 현재 local worktree의 미커밋 변경을 검증하는 원격 run은 없다.

## 범위

- 로컬 Git ref, workflow 정의, 마지막으로 문서화된 원격 성공 baseline의 관계를 확인한다.
- `github_remote_ci` gate를 current deliverable 기준 fail-closed로 정정한다.
- README·distribution 안내·SDK 배포 문서와 current GOAL 감사 기록을 같은 상태로 동기화한다.

## 제외 범위

- Commit, Push, GitHub Actions 실행/조회, release owner 지정, Play/Provider/법무 승인
- 과거 원격 run의 성공 기록 삭제 또는 부정

## 구현 단계

- [x] Phase 1. 로컬 ref·workflow·기존 remote CI evidence를 감사한다.
- [x] Phase 2. 현재 deliverable의 remote CI gate를 `BLOCKED`로 정정한다.
- [x] Phase 3. 문서·readiness verifier를 동기화한다.

## 결과

- 로컬에 기록된 `origin/main` ref와 `HEAD`는 일치하지만, 마지막으로 문서화된 원격 성공 run은 이전
  baseline만 직접 증명한다. 현재 working tree 변경은 commit·push·해당 SHA workflow success 증거가 없어서
  원격 CI 검증 대상이 아니다.
- `github_remote_ci`는 `GITHUB_CURRENT_HEAD_CI_NOT_VERIFIED`로 `BLOCKED` 처리한다. 이 변경은 과거
  baseline의 성공을 부정하지 않으며, current deliverable을 그 성공으로 대체하지 않는 fail-closed 판정이다.
- 해제 조건은 clean commit, 명시적 사용자 승인에 따른 push, workflow의 Python/Android jobs 성공 및 해당
  head SHA/run URL·완료 시각을 민감정보 없이 status 문서에 기록하는 것이다.
