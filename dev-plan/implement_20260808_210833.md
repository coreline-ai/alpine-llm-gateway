# Probe 전용 PRoot resize topology 진단

작성 일시: `2026-08-08 21:08 KST`

## 목적

`INITIAL_SIZE_ONLY` production 계약을 바꾸기 전에, Samsung arm64에서 Host PTY master,
PRoot tracee의 tty ioctl fd, guest winsize 및 foreground signal 결과가 실제로 같은 terminal 경로인지 분리해 확인한다.
이 문서는 동적 resize를 완료로 선언하지 않는다.

## Samsung 결과

Probe-only `96×28 → 120×40` native PTY experiment에서 다음은 직접 확인됐다.

- tracee `TIOCGWINSZ` fd는 Host Native PTY slave와 같은 device이며 tty였다.
- Host master `TIOCSWINSZ` 호출은 성공했다.
- requested-size `TIOCGWINSZ` pair는 extension 전후 모두 `40×120`을 관찰했다.
- 그 이후 같은 guest PTY에서 `28×96`으로 되돌리는 `TIOCSWINSZ`는 관찰되지 않았다.
- direct raw-syscall helper는 `tty_winsize_state=dynamic`을 반환했고, tracee class 분류는 BusyBox의
  requested-size post-extension read와 helper read를 모두 같은 slave PTY의 `40×120`으로 확인했다.
- Native PTY exec 전 `COLUMNS`/`LINES`를 제거한 뒤 BusyBox `stty size`도 `40 120`을 반환했다. 따라서
  `GUEST_WINSIZE_NOT_PROPAGATED`는 재현 가능한 root cause가 아니며 PRoot production patch는 필요하지 않다.
- 그러나 armed foreground shell `WINCH` trap은 수신되지 않았다. 따라서 public `DYNAMIC` capability,
  `SIGWINCH`, resize storm/rotation, TUI, orphan 검증은 아직 통과하지 않았다.
- tracee fork 전 `SIGWINCH=SIG_DFL` 정정과 host-local recorder self-test 뒤에도 self-test 외 `SIGWINCH`는
  `host=0`, `tracee-stop=0`, `ptrace-restart=0`이었다. Android master `TIOCSWINSZ`는 winsize만 변경하며
  kernel signal event를 만들지 않는 것으로 재현됐다. terminal fd의 foreground group만 사용한 native notify
  candidate도 guest trap을 일관되게 만들지 못해 production source/APK에서 제거했다.

guest winsize는 확인됐지만 signal 전달은 source-level 해결이 아니다. production은 계속
`INITIAL_SIZE_ONLY`와 `TERMINAL_RESIZE_UNSUPPORTED`를 유지하며 release gate는
`GUEST_SIGWINCH_NOT_PROPAGATED`로 `BLOCKED`다.
