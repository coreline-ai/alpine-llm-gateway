## 개발 목적

기존 `sample/`과 분리된 `demo-chatbot/` Android 앱을 만든다. 사용자는 OAuth 연결이 완료된 Claude/Anthropic, Gemini, OpenAI-compatible LLM 프로필을 모두 목록에서 확인하고, 대화별 또는 다음 요청별로 원하는 프로필과 모델을 선택해 일반적인 스트리밍 챗봇으로 사용할 수 있어야 한다.

## 개발 범위

- `demo-chatbot/` 독립 Android application 모듈을 추가한다.
- Provider 연결 정보를 등록·수정·삭제하고 OAuth 연결·재연결·로그아웃할 수 있게 한다.
- 인증 상태가 정상인 모든 Provider 프로필을 챗봇 선택 목록에 표시한다.
- 선택된 프로필 하나에만 현재 대화 이력과 새 사용자 메시지를 전송한다.
- Claude/Anthropic, Gemini, OpenAI-compatible adapter를 공통 chat session 계약으로 감싼다.
- 응답을 SSE로 스트리밍하고 전송 중 취소, 오류, 재로그인 상태를 UI에 반영한다.
- assistant 메시지에 실제 응답 Provider 이름과 모델을 기록해 전환 후에도 출처를 구분한다.
- Provider 프로필의 비민감 설정은 앱 내부에 저장하고 OAuth token은 기존 Android Keystore 저장소만 사용한다.
- JVM 테스트, Android instrumentation과 Samsung 실기기 smoke test를 추가한다.

## 구현 결정

- 새 디렉터리와 Gradle module 이름은 `demo-chatbot/`, `:demo-chatbot`으로 고정한다.
- package/application ID는 `dev.alpine.llm.demo`로 사용한다.
- `minSdk 26`, `compileSdk/targetSdk 36`, Java/Kotlin 17을 기존 모듈과 맞춘다.
- UI는 새 Compose compiler 구성을 추가하지 않고 XML, AppCompat/Material, RecyclerView, ViewModel로 구현한다.
- 앱은 `implementation(project(":android"))`로 현재 Android gateway library를 직접 소비한다.
- 챗봇 기본 전송 경로는 `OAuthLlmSession.stream()`으로 한다.
- UI와 Provider 구현 사이에는 `ChatCompletionSession` 인터페이스를 두어 향후 Host Bridge/Alpine 경로를 추가해도 UI를 바꾸지 않게 한다.
- 대화는 ViewModel 메모리에 유지해 회전에는 보존하되 앱 재시작 후 영구 복원은 하지 않는다.
- 비민감 Provider 프로필은 app-private SharedPreferences JSON에 저장하고 token은 기존 `OAuthTokenStore`에만 둔다.
- Provider 전환 시 기존 대화 이력은 유지하며, 다음 요청부터 선택한 Provider로 보낸다.
- 연결 상태가 `Authenticated`인 프로필만 채팅 선택 목록에 포함하고 `ReauthenticationRequired`는 연결 관리 화면에만 표시한다.

## 참조 GUI에서 채택할 패턴

- OpenMinis의 `CHOOSE_TYPE → CHOOSE_CREDENTIAL → CONFIGURE` 흐름 중 OAuth 전용 데모에 필요한 `CHOOSE_TYPE → CONFIGURE` 두 단계를 사용한다.
- Provider마다 색상과 설명을 가진 선택 카드를 제공하고 같은 유형의 복수 profile을 허용한다.
- 기존 label과 충돌하면 `Claude 2`, `Gemini 2`처럼 자동 증가한 기본 표시명을 제안한다.
- Provider 유형을 선택하면 해당 유형의 기본 API endpoint placeholder와 필수 필드 설명을 표시한다.
- 저장과 OAuth 연결을 분리해 잘못된 설정도 수정할 수 있게 하고, 연결 중·연결됨·재로그인 필요·연결 안 됨 상태를 행에 표시한다.
- 연결된 credential 원문은 표시하지 않고 상태와 만료 시각만 표시한다.
- profile 상세에서 수정, OAuth 연결/로그아웃, 삭제를 제공하고 삭제 전 확인한다.
- OpenMinis의 API key/manual bearer UI는 credential 비노출 원칙 때문에 가져오지 않는다.

## 핵심 데이터 계약

## 사전 확인이 필요한 외부 조건

- 각 Provider가 Android public OAuth client와 현재 callback 방식을 실제로 허용하는지 확인해야 한다.

- Gemini Android client에서 loopback redirect가 허용되지 않으면 App Link/custom scheme 구현이 별도 선행 작업이다.
- OpenAI-compatible Provider는 OAuth endpoint와 public-client 등록을 제공하는 경우에만 OAuth 연결할 수 있다.
