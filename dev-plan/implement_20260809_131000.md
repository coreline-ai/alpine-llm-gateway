# README Screenshot Metadata Safety 계획

작성 일시: `2026-08-09 13:10:00 KST`

## 목적

GOAL Phase 8은 README screenshot의 크기·링크뿐 아니라 민감정보 제외 여부를 로컬에서 검사해야 한다.
기존 UI verifier는 source dimensions, README preview width 및 path만 확인했다. PNG ancillary metadata
(`tEXt`, `zTXt`, `iTXt`, `eXIf`, `tIME`)가 future screenshot에 추가되면 account/device/location 등
비화면 metadata가 저장소에 들어갈 수 있으므로, 현재 갤러리에 필요한 image/color chunk만 허용한다.

## 범위

- design token에 README screenshot PNG allowed chunk contract를 추가한다.
- UI verifier가 PNG chunk 순서·경계와 forbidden metadata chunk를 fail-closed로 검사하게 한다.
- metadata chunk를 포함한 synthetic PNG가 거부되는 Python regression을 추가한다.
- README/검증 기록에 자동 검사 범위와 한계를 명시한다.

## 제외 범위

- OCR/vision 기반 화면 텍스트 판정 또는 사용자 계정·token·terminal output의 자동 의미 판정
- screenshot 내용의 제품 UX 변경 및 새로운 screenshot 생성
- 실제 Provider/OAuth/Doze/reboot/Play/원격 CI

## 안전 조건

- 허용하지 않은 PNG chunk는 metadata로 오인될 수 있으므로 CI에서 실패시킨다.
- pixel payload는 해석·전송·재인코딩하지 않고 PNG 구조만 검사한다.
- README의 공개 가능 화면 선택 책임을 자동화로 대체하지 않으며, manual review 경계는 유지한다.

## 구현 결과

- `docs/design/alpine-product-tokens.json`에 README gallery가 허용하는 PNG chunk를 명시했다.
  현재 공개 image는 `IHDR`·color metadata·`IDAT`·`IEND`만 사용한다.
- `verify-ui-design-contract.py`는 PNG size upper bound, signature/length/CRC/IEND boundary를 검증하고,
  allowlist 밖 chunk를 fail-closed로 거부한다. 따라서 text, compressed text, international text, EXIF, time
  같은 metadata chunk와 과대 PNG는 CI에서 통과할 수 없다.
- synthetic safe PNG, text metadata injection, corrupted CRC, oversized payload regression을 추가했다. 이는 pixel을 OCR하거나
  visible screen content를 의미 분석하지 않으므로, 실제 공개 가능 화면 선택은 계속 human review 책임이다.
- sandbox 밖 Gateway localhost 회귀를 포함한 `python3.11 -m unittest discover -s tests -v`는
  **115/115 PASS, no skip**였다. UI design verifier와 `git diff --check`도 통과했다.
