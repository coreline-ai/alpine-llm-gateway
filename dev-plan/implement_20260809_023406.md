# Phase 1d: PRoot post-TIOCGWINSZ read lifecycle trace

작성 일시: `2026-08-09 02:34:06 KST`

## 목적

Samsung arm64에서 PRoot terminal은 initial `stty size` 이후 별도 고정 input batch를 처리하지 못한다.
Relay24의 memfd·socket·no-request control과 Relay25의 Android ioctl seccomp-filter 제거 뒤에도 이 현상이
남았으므로, 이번 단계는 **성공한 guest `TIOCGWINSZ` 뒤의 read lifecycle**을 source-level fixed stage로
확인한다. 단, PRoot seccomp 가속은 일반 `read(2)`를 `PTRACE_CONT`로 통과시킬 수 있으므로, read 관찰의
부재를 결론으로 쓰려면 반드시 seccomp-off control을 함께 실행한다.

## 범위와 금지 사항

- `Relay26`은 `:alpine-runtime-probe`에만 패키징하는 disposable PRoot artifact다.
- record는 `tiocgwinsz_exit_ok`, `read_enter`, `read_exit_nonempty`, `read_exit_eof`, `read_exit_error`의
  고정 enum만 사용한다. terminal bytes, command, PID, fd 값, credential, path를 기록하지 않는다.
- artifact는 production Runtime pack, SDK, integrated-app APK와 source offer에 포함하지 않는다.
- command replay, input retry, polling/FIFO, `/proc` fd 재개방, signal injection은 추가하지 않는다.

## 구현

- [x] OpenMinis PRoot pinned commit `8cf13e9`의 `src/syscall/syscall.c`에 opt-in source-level recorder를
  추가했다.
- [x] recorder는 `PROOT_TTY_POST_WINSIZE_INPUT_TRACE`가 있을 때만 app-private diagnostic file에 append한다.
- [x] Probe manifest/debug gate, checksum lock, boundary test, Gradle checksum task를 추가했다.
- [x] `tty_trace_post_winsize_input` intent/script flag를 추가하고 이 trace mode에서는 virtual resize request를
  no-request control로 고정했다. 이는 resize capability를 제공하지 않는다.
- [x] `Relay27`은 첫 successful guest `TIOCGWINSZ`의 child와 그 parent의 exit/wait/read lifecycle만
  fixed enum으로 기록한다. 이 variant도 `:alpine-runtime-probe`에만 패키징되고, 명시적 seccomp-off control에서만
  read coverage를 해석한다.

## Samsung 결과 및 해석 보정

| 관찰 | 결과 |
|---|---|
| Probe artifact·runtime command·initial terminal prompt | PASS |
| 기본 seccomp run: successful guest `TIOCGWINSZ` exit | 6회 기록 |
| 기본 seccomp run: `read(2)` enter | 0회 기록. 일반 `read`가 seccomp fast path에서 trace되지 않으므로 단독 증거로 사용 불가 |
| seccomp-off control: successful guest `TIOCGWINSZ` exit | 3회 기록 |
| seccomp-off control: 이후 `read(2)` | `read_enter` 1회, `read_exit_nonempty` 1회 |
| 두 run의 fixed marker/helper/follow-up input | 미응답 |
| host-only PTY `TIOCGWINSZ → later input` | PASS (기존 control) |
| production dynamic resize | 미승격 |

초기 seccomp run의 `read_enter=0`은 PRoot source의 seccomp acceleration이 일반 `read`에 syscall-exit
trace를 요청하지 않아 recorder가 호출되지 않는 특성으로 해석을 보정했다. 동일 Probe의 seccomp-off control은
성공한 `TIOCGWINSZ` 뒤 적어도 하나의 guest `read` enter와 non-empty exit를 관찰했다. 따라서 Relay26은
**PRoot가 모든 post-`TIOCGWINSZ` read event에 도달하지 못한다는 결론을 지지하지 않는다.** 하지만 해당 read가
terminal command를 정상 완료시키지 못했고 marker/helper/follow-up은 계속 미응답이므로, post-ioctl terminal
lifecycle failure 자체는 남아 있다. Relay26은 tracee·fd·parent-child 관계를 기록하지 않으므로 정확한 내부 지점은
확정하지 않는다.

Relay27 seccomp-off control은 첫 `TIOCGWINSZ` caller(child)의 `target_exit_enter` 1회, parent의
`parent_wait_inflight`/`parent_wait_exit` 각 1회, `parent_read_enter`/`parent_read_exit_nonempty` 각 1회를
기록했다. 즉 initial `stty size` child 종료와 parent wait는 완료되고, 바로 뒤 별도 fixed input도 parent의
`read(2)`에서 non-empty로 반환된다. 그럼에도 acknowledgement·marker·helper/follow-up output은 없었다.
Relay27은 terminal bytes, fd, PID와 이후 shell parser/write 상태를 기록하지 않으므로 이 결과만으로 guest shell
parser, PRoot syscall interleaving, PTY output pipeline 중 정확한 하나를 단정하지 않는다. 다만 기존의
"post-ioctl event loop가 read에 전혀 도달하지 않는다"는 가설은 폐기한다.

## 판정

- [x] `TIOCGWINSZ` 이후 별도 input failure가 Host PTY 일반 동작, virtual resize request, Android ioctl
  seccomp filter, stdin/stdout/stderr sharing만으로 설명되지 않음을 다시 확인했다.
- [x] seccomp-off Relay26 control에서 post-`TIOCGWINSZ` `read_enter`/`read_exit_nonempty`를 관찰해,
  기존의 "모든 read enter 부재" 해석을 철회했다.
- [x] Relay27로 target child exit → parent wait exit → parent non-empty read까지의 fixed lifecycle을 확인했다.
  동적 resize를 구현할 정도의 root cause 또는 output completion 증거는 아직 없으므로 product behavior는 바꾸지 않는다.
- [x] 로컬 OpenMinis PRoot의 `origin/master`와 pinned `8cf13e9`가 동일함을 확인했다. 포함된
  `--native-offload`은 선택한 `execve`를 abstract socket host handler로 넘기는 기능이므로 interactive guest
  terminal backend/resize 해법이 아니며, credential·command boundary도 넓히므로 후보에서 제외했다.
- [x] 제품 계약 `INITIAL_SIZE_ONLY` 및 `TERMINAL_RESIZE_UNSUPPORTED`를 유지했다.
- [x] Relay26은 Probe-only artifact boundary를 유지한다.
- [ ] maintained PRoot upstream terminal/job-control fix 또는 PRoot를 통과하지 않는 대체 terminal backend를
  설계·검증한다.
- [ ] 그 후보가 `stty size`, `SIGWINCH`, repeated/storm/rotation, representative TUI, terminal close orphan
  matrix를 동일 Samsung에서 모두 통과하기 전에는 `DYNAMIC`으로 승격하지 않는다.

## Relay28 보정 (2026-08-09)

Relay28 seccomp-off control은 첫 successful guest `TIOCGWINSZ` 뒤 target child exit → parent wait → non-empty
parent read와 write의 non-empty 반환을 확인했다. 더 중요한 fixed-printf control은 **첫 get 뒤 단순 input/output이
응답함**을 보였다. 따라서 "첫 get 직후 terminal input/output이 영구 중단"은 정확한 결론이 아니다.

기존 second-`stty` marker는 command substitution을 사용했고 응답하지 않았다. Relay29는 second `TIOCGWINSZ`의
enter와 success exit을, Relay30 direct-helper control은 target stdout/exit와 terminal delivery를 확인했다. 따라서
그 marker의 무응답을 일반 PRoot post-get failure로 단정하지 않는다. 제품은 계속 `INITIAL_SIZE_ONLY`이며 세부는
`implement_20260809_064200.md`를 따른다.
