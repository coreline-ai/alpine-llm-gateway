## 목적

Alpine terminal 또는 command의 마지막 Runtime process가 종료될 때 foreground service가 명시적으로
`stopForeground(STOP_FOREGROUND_REMOVE)`를 수행하고, Samsung에서 service·알림이 남지 않는지 검증한다.
Doze, reboot, battery restriction은 변경하지 않는다.

## 범위와 안전 경계

- `alpine-runtime-background-android`의 process-lease → foreground service stop 경로를 수정·검증한다.
- Android instrumentation은 service lifecycle과 앱 소유 notification의 생성/제거만 관찰한다.
- Terminal command, Provider credential, prompt, PID, raw terminal output은 test result나 문서에 기록하지 않는다.
- notification permission이 거부된 OS에서도 service stop contract가 false-positive가 되지 않도록 service lifecycle을
  독립적으로 확인한다.
- PRoot dynamic resize, package live repository, Doze/reboot, 실제 Provider 계정, Play/x86_64 E2E는 이 범위에
  포함하지 않고 기존 상태를 유지한다.

## Phase 1. Stop 경로 감사와 명시적 해제

- [x] `RuntimeForegroundServiceController.stop()`의 direct `stopService()`는 Android Service lifecycle상 valid한
  stop 경로임을 확인하고, `RuntimeForegroundService.onDestroy()`에서
  `stopForeground(STOP_FOREGROUND_REMOVE)`를 명시 호출하도록 보강했다. notification의 **작업 중지** action은
  기존 `ACTION_STOP → stopForeground(REMOVE) → stopSelf` 경로를 유지한다.
- [x] 마지막 process 종료와 duplicate `STOPPED`가 foreground lease를 재시작하지 않는 회귀를 추가했다.

## Phase 2. Android 실기기 관찰 회귀

  foreground notification이 남지 않음을 확인한다.
- [x] Samsung strict run 뒤 test package와 permission을 제거하고 `dev.alpine.integrated` APK를 restore/cold start한다.

## 완료 조건

- terminal/command 마지막 process 종료가 explicit foreground removal까지 연결된다.
- Samsung에서 FGS lifecycle을 재현 가능하게 검증하거나 OS permission 상태 때문에 불가능한 부분을 `NOT_RUN`으로
  정확히 분리한다.
- 기존 fast chat와 Alpine Runtime의 stop/recovery contract를 변경하지 않는다.

## Samsung 실행 결과

- 기본 permission 상태의 `:alpine-runtime-background-android:connectedDebugAndroidTest` 1/1은 last process가
  FGS/service state를 종료하는지 확인했다.
- strict notification run은 외부 ADB에서 test-only package에만 runtime permission을 부여한 뒤
  `requireNotificationVisibility=true` instrumentation argument로 실행했다. terminal·command overlap, last
  `STOPPED`, duplicate `STOPPED` 뒤 foreground notification removal까지 1/1 PASS였다.
- strict run이 끝난 뒤 permission과 test APK를 제거하고 latest integrated debug APK를 replace install·cold start했다.
- 이 결과는 test-only merged module에서 공통 FGS adapter를 실기기로 검증한 것이다. 사용자 앱의 permission
  선택 UX, Doze/reboot/battery restriction과 OEM process-kill lifecycle은 범위 밖이며 `NOT_RUN`으로 유지한다.
