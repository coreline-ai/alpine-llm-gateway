# Samsung Provider Compose Host Lifecycle Regression 계획

작성 일시: `2026-08-09 12:52:08 KST`

## 목적

Samsung 계측에서 `ProviderScreensInstrumentedTest`의 Compose UI 9개가 실제 제품 오류가 아니라
`createEmptyComposeRule`과 별도 `ActivityScenario` host 사이의 Compose root 등록 경쟁으로 실패한 것을
test-only fixture에서 재현·보강한다. 제품 Provider 화면, OAuth/credential 경계, 기기 보안 정책은 변경하지
않는다.

## 범위와 안전 조건

- 대상은 `alpine-chat-provider-android`의 `androidTest` Provider UI host fixture뿐이다.
- synchronous activity launch, lifecycle teardown, Compose root 등록 대기만 추가한다.
- 화면 wake, Keyguard bypass, Doze/reboot/battery 설정 변경, 실제 Provider 호출은 하지 않는다.
- Provider 원문 오류, credential, prompt, Samsung serial을 source·보고서·screenshot에 기록하지 않는다.
- 계측 후 Demo/Probe/test package를 제거하고 최종 `dev.alpine.integrated`만 재설치·cold start한다.

## 구현 단계

- [x] Phase 1. Samsung 실패를 XML 결과로 분리해 9개 UI test가 `No compose hierarchies found`로
  실패하고 비-UI Provider test 3개는 통과한 fixture lifecycle 문제임을 확인한다.
- [x] Phase 2. `ActivityScenario` 대신 synchronous `startActivitySync`와 `RESUMED` 대기, lingering
  activity teardown, test-root 등록 대기를 test-only host에 구현한다.
- [x] Phase 3. Samsung에서 Provider 12/12 및 Android core 3/3, integrated 10/10 회귀를 재실행하고
  최종 integrated product-only cold start를 확인한다.
- [x] Phase 4. 검증 기록·GOAL audit을 현재 증거 범위로 동기화한다.

## 결과

- `ProviderScreensInstrumentedTest`는 각 test 전에 남아 있는 test Activity를 종료한 뒤 명시적으로
  `RESUMED` 상태가 된 host에 Compose content를 등록한다.
- content 등록 직후 명시 root tag가 test rule에 관찰될 때까지 대기해 첫 assertion이 root registration과
  경쟁하지 않는다.
- Samsung 재실행: Android OAuth core **3/3**, Provider **12/12**, integrated fast chat **10/10**,
  모두 failure/error/skip 없이 통과했다.
- 최신 `:integrated-app:assembleDebug` APK를 replace install하고 cold start했으며, 최종 설치 package는
  `dev.alpine.integrated`만 확인했다.

## 비범위·잔여 조건

- 이 fixture 보강은 실제 OAuth/API 계정 E2E, 실제 429·5xx·비정상 SSE, Provider idempotency 계약을
  대신하지 않는다. 해당 항목은 `NOT_RUN`/`NOT_CONFIRMED`다.
- PRoot dynamic terminal resize, x86_64 emulator, reboot/Doze/process-kill과 공개 배포 gate도 변경하지 않는다.
