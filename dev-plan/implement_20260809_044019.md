## Relay29·Relay30 보정 (2026-08-09)

Probe-only Relay29 seccomp-off control은 first successful guest `TIOCGWINSZ` 뒤, marker가 요청한 second
`TIOCGWINSZ`가 enter와 success exit에 모두 도달함을 확인했다. marker completion은 여전히 false였으므로
blocker를 second ioctl 자체로 단정하지 않는다. Relay30은 기존 command-substitution marker의 child stdout write가
internal pipe일 수 있음을 분리했고, direct fixed helper control에서는 target stdout write·exit와 terminal response가
모두 동작함을 확인했다. 따라서 broad post-get PTY/input failure 진단은 철회한다. actual virtual/physical resize
update와 `SIGWINCH`/repeat/storm/TUI/orphan matrix가 아직 없으므로 제품은 `INITIAL_SIZE_ONLY`를 유지하며 dynamic
resize gate는 계속 `BLOCKED`다. 세부는 `implement_20260809_064200.md`를 따른다.

## Relay31 보완 (2026-08-09)

Relay31은 Relay24 private memfd virtual-winsize source patch와 Relay30 fixed target-output recorder를 결합했다.
Samsung 단일 bounded request에서 memfd store/fd-ready/PRoot apply, direct helper의 `dynamic`, second get success,
helper stdout terminal delivery를 모두 확인했다. 이는 guest query-level virtual size update의 positive evidence다.
그러나 physical host PTY 갱신, foreground `SIGWINCH`, repeat/storm·rotation, `vi`/`nano`/`top`, orphan matrix가
아직 없으므로 production dynamic resize로 승격하지 않는다. 세부는 `implement_20260809_070000.md`를 따른다.

## Relay32 보완 (2026-08-09)

Relay32는 same Probe-only virtual state path의 small/large repeat와 8-step storm에서 fixed helper state marker와
11회 bounded store를 확인했다. query-level repeat/storm이 통과한 것은 positive evidence지만 physical PTY,
foreground `SIGWINCH`, rotation, TUI, orphan matrix는 여전히 남는다. 따라서 resize gate는 계속 `BLOCKED`이고
production은 `INITIAL_SIZE_ONLY`다. 세부는 `implement_20260809_073000.md`를 따른다.
