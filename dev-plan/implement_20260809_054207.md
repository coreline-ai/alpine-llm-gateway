# Phase 1e: PRoot repeated `TIOCGWINSZ` post-read/output 분리

작성 일시: `2026-08-09 05:42:07 KST`

## 목적

Relay27이 첫 successful guest `TIOCGWINSZ` 뒤 child exit → parent wait → parent non-empty read까지
확인했지만 fixed marker가 보이지 않은 원인을 더 좁힌다. 이 단계는 첫 post-read parent syscall과 write
반환을 **고정 enum**으로만 분류하고, 첫 `TIOCGWINSZ` 이후의 단순 `printf`와 두 번째 `TIOCGWINSZ`가 포함된
marker를 구분한다.

## 범위와 금지 사항

- `Relay28`은 `:alpine-runtime-probe`에만 포함되는 disposable diagnostic PRoot artifact다.
- 기록값은 lifecycle, syscall class, stdout/stderr/other class, write result class뿐이다. terminal bytes,
  command, argument, path, PID, fd 숫자, credential은 기록하지 않는다.
- 이 Probe는 user command replay/retry, polling/FIFO, PID/fd 재개방, post-launch signal injection을 하지
  않는다.
- Probe 결과는 dynamic resize 구현이나 product capability 승격의 근거가 아니다.

## 구현

- [x] `proot-tty-relay28-post-read-syscall-flow-trace.patch`를 추가했다.
- [x] 첫 successful guest `TIOCGWINSZ`의 child exit → parent wait → parent non-empty read 뒤 첫 parent
  syscall을 `read`/`write`/`ioctl`/`spawn`/`exec`/`wait`/`exit`/`other` 고정 class로 기록한다.
- [x] 해당 syscall이 write/writev면 standard output/standard error/other의 class와 non-empty/zero/error
  반환 class만 추가 기록한다.
- [x] Relay28 launcher, SHA-256 lock, Gradle preBuild check, parser JSON, module-boundary test, device script
  flag를 추가했다.
- [x] Relay28 mode에서는 이미 관찰한 첫 `TIOCGWINSZ` 뒤 **단순 고정 `printf`**만 보낸다. 이는 shell/input과
  PTY output 경로를 두 번째 `TIOCGWINSZ`에서 분리하기 위한 control이며, runtime resize가 아니다.

## Samsung arm64 결과

| 조건 | 고정 관찰 | 판정 |
|---|---|---|
| Relay28, seccomp-off, 첫 `TIOCGWINSZ` 뒤 기존 second-`stty` marker | target exit, parent wait exit, non-empty parent read, 첫 parent `write`와 non-empty exit | marker 응답 없음 |
| 동일 run의 첫 parent write class | `stderr`, non-empty 반환 | raw error 본문은 수집하지 않음 |
| Relay28, seccomp-off, 첫 `TIOCGWINSZ` 뒤 단순 fixed `printf` | `terminal_resize_responded=true`, parent read 후 write lifecycle은 완료 | first get 뒤 input/output 경로는 동작 |
| Relay28의 첫 write class | `stderr`, non-empty 반환 | 해당 첫 write는 후속 fixed printf의 본문 여부를 식별하지 않음 |
| dynamic resize contract | `false` | product 승격 금지 |

따라서 이전 Relay26/Relay27의 "첫 `TIOCGWINSZ` 뒤 parent가 read에 전혀 도달하지 않는다"는 해석은 이미
폐기됐고, 이번 control로 **첫 get 뒤의 단순 고정 input/output 자체는 응답함**을 확인했다. 응답이 사라지는
조건은 second `TIOCGWINSZ`를 **요청하는** command-substitution marker 경로로 더 좁혀졌다. 후속 Relay29는 second
get의 enter와 success exit을, Relay30 direct-helper control은 target stdout/exit와 terminal delivery를 확인했다.
따라서 second ioctl 이전·이후 일반 PTY failure를 root cause로 단정하지 않는다. 세부는
`implement_20260809_064200.md`를 따른다.

## 판정

- [x] `TIOCGWINSZ` 한 번만으로 terminal input/output이 영구 정지한다는 가설을 제거했다.
- [x] second `TIOCGWINSZ`를 요청하는 marker completion 경로가 남은 조사 범위임을 확인했다.
- [x] product는 `INITIAL_SIZE_ONLY`/`TERMINAL_RESIZE_UNSUPPORTED`를 계속 유지한다.
- [x] Samsung에서 Probe 제거 후 `dev.alpine.integrated`만 설치·cold start 상태로 복구했다.
- [ ] maintained PRoot source-level fix 또는 PRoot를 통과하지 않는 terminal backend가 repeated `TIOCGWINSZ`,
  `SIGWINCH`, repeat/storm/rotation/TUI/orphan matrix를 통과할 때까지 dynamic resize를 승격하지 않는다.
