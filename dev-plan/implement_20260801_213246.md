# implement_20260801_213246.md

작성 일시: `2026-08-01 21:32:46 KST`

이 문서는 Phase 7 이후 남은 P1·P2 기술 후속의 범위를 고정하고, 완료 가능한 구현과 외부 조건이 필요한 검증을 분리하기 위한 작업 문서다.

## 개발 목적

- 장시간 Alpine 작업을 Host가 명시적으로 소유하는 백그라운드 실행 계약을 제공한다.
- 실제 PTY 크기 변경을 guest에 전달하고, 검증된 경우에만 terminal capability를 `DYNAMIC`으로 승격한다.
- 선택형 x86_64, Play Asset Delivery, workspace 모듈의 재사용 경계를 추가한다.
- 실제 Provider E2E와 Gradle 9 전환처럼 외부 조건이 필요한 항목은 재현 가능한 fail-closed 검증 gate로 만든다.

## 개발 범위

- P1: Foreground Service/notification adapter, process death 복구 상태, WorkManager 유지보수 작업 경계.
- P1: native PTY control fd와 resize 계약 수정, Samsung resize storm 및 TUI 검증.
- P1: x86_64 공급망 스크립트·lock·SBOM·16 KiB gate와 emulator 검증 진입점.
- P1: 실제 Provider 계정용 opt-in E2E report/runbook 검증기.
- P2: Play Asset Delivery 기반 선택형 runtime artifact provider.
- P2: Gradle 9 deprecated feature inventory와 CI readiness gate.
- P2: 안전한 파일 작업을 위한 `alpine-workspace-api`/`alpine-workspace-android` 기반 모듈.
- publication, 외부 consumer, 통합 앱과 문서의 신규 모듈 반영.

## 제외 범위

- 사용자 승인 없이 실제 Provider 계정을 호출하거나 비용을 발생시키는 테스트.
- 사용자 승인 없이 Samsung 기기를 재부팅하거나 Doze를 강제하는 파괴적 검증.
- x86_64 시스템 이미지가 없는 환경에서 emulator E2E를 통과한 것으로 기록하는 행위.
- Play Console 업로드, production signing key 생성·사용, Maven 원격 공개.
- Git/SSH/AI runner/자동화 전체 UI와 범용 파일 관리자 구현.
- SDK가 부팅 후 또는 사용자 상호작용 없이 임의로 runtime을 자동 시작하는 동작.

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.

- 문서에 없는 범위 확장은 하지 않는다.

- 기존 프로젝트 API, 공식 SDK, 표준 라이브러리를 우선하고 새 의존성은 범위상 필요할 때만 추가한다.

## 잔여 리스크 / 후속 과제

- 실제 Provider E2E는 계정·비용·모델 승인 뒤에만 실행한다.
- x86_64 최종 지원 표시는 해당 ABI emulator 또는 실기기 E2E가 통과한 뒤에만 한다.
- 실제 reboot/Doze 강제 검증은 사용자 승인과 테스트 창이 필요하다.
- Play Asset Delivery 전체 E2E는 Play Console test track과 서명 AAB가 필요하다.
- 프로젝트 전체 license와 complete corresponding source가 없으면 공개 원격 배포는 계속 차단한다.
