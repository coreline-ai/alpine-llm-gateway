이 문서는 Alpine 통합 패키징을 제외한 Python Gateway 운영 안정성과 자동 검증 범위를 보강하고, 구현이 실제 Provider 계정 연동이나 신규 프로토콜 기능으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

Python 표준 라이브러리 Gateway가 일시적인 Provider 장애에 제한적으로 복구하고, 반복 장애 시 불필요한 요청을 차단하도록 retry/backoff/circuit breaker를 추가한다. 동일 변경을 설정·문서·회귀 테스트에 연결하고 Python, Android Library, sample, demo 검증을 CI와 로컬 릴리스 스크립트에서 재현 가능하게 만든다.

## 개발 범위

- Python Provider HTTP open/status 단계에 제한된 retry를 적용한다.
- 408, 429, 선택된 5xx와 연결 실패만 retryable로 분류한다.
- `Retry-After`, 지수 backoff, jitter와 최대 대기시간을 적용한다.
- Streaming은 HTTP 연결과 상태 응답까지만 재시도하고 stream을 연 뒤에는 재시도하지 않는다.
- Provider 인스턴스별 thread-safe circuit breaker를 적용한다.
- retry/circuit breaker 설정을 `Settings`, Provider factory, 예제 설정과 README에 연결한다.
- Python·Android·sample·demo 검증을 GitHub Actions와 로컬 릴리스 스크립트에 반영한다.

## 제외 범위

## 잔여 리스크 / 후속 과제

- 실제 Provider credential 기반 408/429/5xx, 비정상 SSE와 `Retry-After` E2E는 수행하지 않았다.
- Chat Completion POST는 Provider별 idempotency 계약이 없으면 연결 실패 재시도 시 중복 처리 가능성이 있으며, 설정값 1로 비활성화할 수 있다.
- circuit breaker 상태는 프로세스 메모리와 Provider 인스턴스 단위이며 재시작 시 초기화된다.
- GitHub Actions workflow는 YAML parsing과 동일 로컬 명령으로 검증했지만 원격 GitHub runner 실행 결과는 push 이후 확인해야 한다.
- Python 이미지·function tool 확장, 실제 OAuth Provider 검증과 Alpine 완전 통합은 이번 범위에서 제외했다.
