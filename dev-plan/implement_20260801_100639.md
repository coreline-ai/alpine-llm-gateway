# implement_20260801_100639.md

작성 일시: `2026-08-01 10:06:39 KST`

이 문서는 직전 개발에서 남은 후속 항목의 범위를 고정하고, 실제 Provider 계정에 위험한 오류를 강제로 발생시키거나 완전한 Markdown·웹 검색 제품으로 범위가 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

Provider의 429·5xx·비정상 stream·timeout을 결정적으로 재현해 앱의 redacted 오류와 재시도 흐름을 E2E로 검증한다. assistant Markdown에는 모바일에서 필요한 표, 명시적 안전 링크 열기와 경량 코드 강조를 추가한다. 앱이 웹 도구 없이 최신 정보나 외부 검증을 수행했다고 오인시키지 않도록 요청 감지·지침·응답 검증 경계를 추가한다.

## 개발 범위

- fake Provider/session으로 HTTP 429, HTTP 503, 잘못된 stream JSON, 중단된 stream과 timeout을 결정적으로 주입한다.
- 각 오류가 원문·토큰·endpoint를 노출하지 않는 사용자용 실패 상태로 변환되고, 가능한 경우 같은 요청을 중복 user message 없이 재시도하는지 검증한다.
- Android transport/adapter 단위에서는 non-2xx stream 응답과 비정상 SSE event의 안전한 변환 계약을 보강한다.
- Markdown 표를 native Compose로 표시하고 작은 화면에서는 표 영역만 가로 스크롤한다.
- `http`·`https` 링크만 링크로 인식하며, 탭 후 확인 dialog를 거쳐 사용자가 명시적으로 열게 한다.
- fenced code의 알려진 언어에 의존성 없는 경량 token 강조를 적용하고 알 수 없는 언어는 plain monospace로 유지한다.
- 최신·현재·오늘·웹 확인 요구를 로컬에서 감지해 “외부 도구가 없으면 확인했다고 주장하지 않는다”는 bounded system 지침을 추가한다.
- 실제 응답이 웹을 확인했다고 허위 주장하는 안전 패턴이면 같은 Provider·모델·Assistant mode로 최대 1회 교정한다.
- README, 디자인 가이드와 개발 계획에 실제 지원 범위와 잔여 리스크를 기록한다.

## 제외 범위

- 실제 운영 Provider 계정에 의도적으로 rate limit 또는 장애를 발생시키는 부하·오류 요청
- Provider 장애 발생 시점에 의존하는 비결정적 실계정 429·5xx 자동 테스트
- CommonMark/GFM 전체 호환, HTML/WebView 렌더링, 원격 이미지 자동 로드
- 완전한 IDE급 syntax highlighter, 임의 URI scheme 실행, 링크 자동 열기
- 앱 내부 브라우저·검색 엔진·웹 검증 도구 추가와 답변의 일반적인 사실 정확성 자동 판정
- 별도 judge 모델, 2회 이상 자동 교정, hidden reasoning 저장
- GitHub push/원격 CI, Provider별 idempotency 계약 확정과 Alpine 완전 통합 패키징

## 잔여 리스크 / 후속 과제

- 최신성 guard는 명시적 웹 확인 주장만 탐지하는 안전 경계이며 답변 전체의 사실 정확성을 판정하지 않는다.
- 실제 Provider 계정에 의도적으로 429·5xx·잘린 SSE를 발생시키지 않았다. 운영 장애 시점의 실계정 관찰은 계정·비용 위험 없이 별도 수행해야 한다.
- Markdown은 bounded subset이며 task list, 수식, 각주, 원격 image와 완전한 CommonMark/GFM 호환은 제공하지 않는다.
- 링크 표시는 host 문자열을 그대로 보여주지만 피싱 평판 판정이나 앱 내부 브라우저 격리는 제공하지 않는다.
- GitHub push/원격 CI, Provider별 idempotency 계약 확정과 Alpine 완전 통합 패키징은 다음 독립 계획으로 남긴다.
