# Package metadata bounded-total 계획

작성 일시: `2026-08-09 12:20:00 KST`

## 목적

Package catalog는 소비 앱 또는 bundled snapshot이 공급하는 display-only metadata다. 기존 합계 계산은
`Math.addExact`를 사용해 비정상적으로 큰 non-negative byte 값들의 합이 `Long` 범위를 넘으면 Package UI가
예외로 종료될 수 있다. 이 값은 authorization이나 실제 `apk` argv에는 사용되지 않지만, 손상되거나 잘못
생성된 snapshot이 UI 안정성을 해치지 않도록 합계를 포화 처리하고 정확하지 않은 총계를 명시적으로 표시한다.

## 범위

- archive/payload 합계를 overflow 없이 계산하고 overflow 여부를 API result에 보존한다.
- UI는 overflow된 합계를 용량 수치로 오인해 표시하지 않고, snapshot 총계가 표시 범위를 넘었다는
  제한 안내를 표시한다.
- allowlist, approval, package metadata authorization 분리와 fixed `apk` argv는 변경하지 않는다.
- API/Compose 자동 회귀, Samsung non-destructive 계측, static verifier와 문서를 동기화한다.

## 제외 범위

- live package solver, repository freshness/network/capacity/disk-full/cancel E2E
- rootfs source mirror, PRoot resize, 실제 Provider/Play/Doze/reboot/x86_64 gate
- package metadata를 실제 설치 허가 또는 정확한 dependency-total source로 승격하는 변경

## 안전 조건

- overflow metadata는 process/UI crash가 아니라 bounded display state가 된다.
- saturation value를 실제 설치 용량의 정확한 수치로 표시하지 않는다.
- metadata는 계속 display-only이며, 실제 mutation은 allowlist·사용자 승인·simulation success 뒤에만 가능하다.
- raw package output, path, credentials 또는 host-private 상태를 결과 UI에 추가하지 않는다.

## 구현 결과

- `RuntimePackageEstimate.totalBytesOverflowed`를 추가했다. `RuntimePackageCatalog`는 direct-package
  byte 합산이 `Long` 범위를 넘으면 `Long.MAX_VALUE`로 포화하고 해당 flag를 설정한다. `isComplete`는
  missing metadata뿐 아니라 overflow된 total에서도 `false`다.
- Compose Package summary는 flag가 있으면 합계 byte 수치를 렌더링하지 않고 snapshot 표시 범위 초과와
  실제 설치 용량으로 사용하면 안 된다는 bounded 안내만 표시한다.
- catalog는 계속 표시 전용이다. allowlist, explicit approval, fixed `apk --simulate`, preflight success
  뒤 mutation이라는 authorization/dispatch 순서는 바꾸지 않았다.
