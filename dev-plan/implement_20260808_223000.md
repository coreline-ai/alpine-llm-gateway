# Phase 1b: PRoot-managed SIGWINCH relay Probe

작성 일시: `2026-08-08 22:30 KST`

## 배경

Samsung arm64 Probe는 동일 PTY의 guest winsize와 BusyBox `stty size`가 Host `TIOCSWINSZ` 후
정상적으로 바뀜을 확인했다. 미해결 문제는 Android PTY가 자동 `SIGWINCH` event를 만들지 않아
foreground guest shell trap과 TUI 재배치가 일어나지 않는다는 것이다. production은 계속
`INITIAL_SIZE_ONLY`/`TERMINAL_RESIZE_UNSUPPORTED`를 유지한다.

## 가설과 설계

Probe 전용 PRoot artifact에 다음 **source-level relay**를 추가한다.

1. Host native PTY bridge는 `TIOCSWINSZ` 성공 후 app-private AF_UNIX socket으로 fixed one-byte relay
   요청만 보낸다. Probe-only session supervisor는 direct PRoot child 한 개에만 `SIGWINCH`를 전달하고,
   PRoot source가 `launch_process()`에서 알고 있는 최초 tracee에만 signal을 relay한다. `/proc` 재탐색,
   외부 guest PID 저장, command parsing, Host foreground-group blind dispatch는 사용하지 않는다.
2. Supervisor는 `setsid`·controlling TTY·direct-child PRoot·`signalfd(SIGCHLD)`와 poll 기반 socket loop로
   session을 관리한다. 주기 polling이나 terminal payload logging은 사용하지 않는다.
3. Android는 PRoot의 blocking `waitpid`를 외부 signal 뒤 자동 재시작하므로, relay16 Probe에서는
   PRoot SIGWINCH handler가 source-level `launch_process()` parent branch에서만 저장한 첫 tracee에
   `SIGWINCH`를 dispatch한다. PRoot가 기록한 tracee signal stop/restart와 shell trap으로 delivery를
   검증한다. 이 후보는 initial shell만 대상으로 하므로 foreground job/TUI 지원을 의미하지 않는다.
4. 이 방법은 initial shell trap을 판정하기 위한 후보일 뿐, foreground process group이 바뀌는 TUI까지
   지원한다는 뜻이 아니다. full matrix가 통과하기 전 production contract/API는 변경하지 않는다.
5. fixed literal diagnostic stage만 Probe-private record에 남긴다:
   `host_received`, `relay_supervisor_direct_proot_dispatched`, `relay_primary_tracee_dispatched`,
   `tracee_stopped`, `tracee_restarted`.

이 접근이 shell trap을 보장한다고 가정하지 않는다. Samsung matrix에서 아래를 모두 증명할 때만
production `DYNAMIC` 승격을 검토한다.

## 승격/실패 기준

- `DYNAMIC`은 guest `stty`, raw helper, foreground `WINCH` trap, repeated/storm/rotation, 대표 TUI,
  close 후 orphan 없음이 Samsung에서 independent assertions로 통과해야 한다.
- 어느 하나라도 불명확하거나 실패하면 production code/API/UI는 바꾸지 않고, diagnostic artifact만
  Probe에 남기며 release gate `GUEST_SIGWINCH_REPEAT_STRESS_UNSUPPORTED`를 BLOCKED로 유지한다.
- 이 Probe artifact는 `:integrated-app`, SDK pack, source offer, release SBOM에 넣지 않는다.

## Samsung 결과 — 2026-08-08

- relay16 기본 Probe는 initial shell `WINCH` trap과 supervisor → direct PRoot → PRoot primary tracee →
  ptrace stop/restart fixed-stage 계약을 확인했다. 이는 **초기 shell 한 번**의 diagnostic evidence이며
  production 기능이 아니다.
- Probe 순서를 보정했다. BusyBox `ash`의 pending trap은 interactive input read가 반환된 뒤 dispatch될 수
  있으므로, resize 뒤 trap을 먼저 기다리지 않고 고정 marker command를 즉시 write하도록 바꿨다. 이 변경은
  guest polling이나 product API 변경이 아니다.
- 보정 뒤에도 기본 Probe에서 `SIGWINCH` 1회는 trap까지 도달했지만, 그 직후 write한 고정 `printf` command
  acknowledgement와 `stty` marker, helper follow-up이 모두 응답하지 않았다. 즉 marker 대기 순서나
  `stty` 자체가 아니라 **PRoot ptrace reinjection 뒤 interactive input command path가 재개되지 않는 현상**으로
  범위를 좁혔다. 이 원인은 source-level candidate이며, 아직 upstream root cause로 단정하지 않는다.
- stress Probe는 `120x40 ↔ 80x24` 반복과 8회 storm을 요청했다. supervisor/PRoot/primary-tracee relay
  input은 11건, source-level tracee stop/restart는 19건이 기록됐지만, 안전 marker와 helper command가
  응답하지 않았다. terminal trap marker는 4회까지만 관측됐다.
- 다음 후보는 direct primary-tracee `kill(SIGWINCH)` relay를 더 확장하는 것이 아니라, maintained PRoot
  terminal/job-control hook 또는 PRoot를 거치지 않는 controlling-terminal architecture에서 signal delivery 뒤
  interactive read 재개와 foreground job ownership을 함께 보장하는 것이다. 후보 artifact는 아래 순서로만
  승격 검토한다: `SIGWINCH → fixed printf → stty` 단일 회귀, repeated/storm, rotation, foreground TUI,
  close/orphan matrix.
- 결론: initial signal delivery는 증명됐지만 interactive terminal semantics는 미해결이다. product는
  `INITIAL_SIZE_ONLY`, `TERMINAL_RESIZE_UNSUPPORTED`, `ALPINE_TERMINAL_RESIZE_CHANNEL=unsupported`를 유지한다.
