## 개발 목적

- Android 직접 Provider 기반 빠른 채팅을 유지하면서 Alpine 작업 모드의 실제 작업 흐름을 완성한다.
- PRoot guest terminal resize를 source-level로 해결하거나, 검증되지 않은 동적 capability를 노출하지 않는 안전한 계약을 유지한다.
- Runtime, workspace, Gateway의 재사용 가능한 모듈 경계를 지키고 Samsung 실기기와 자동 테스트로 회귀를 막는다.

## 개발 범위

- PRoot PTY/winsize/SIGWINCH 전달 경로 분석·수정·증거화
- terminal/session UI, bounded scrollback, control key와 세션 상태 개선
- app-private workspace, editor, SAF import/export/share 보안 경계 보강
- package/dev-tool workflow, Gateway lifecycle과 복구 흐름 완성
- Provider 정책 문서, UI/accessibility/device regression, local release/security 검증

## 제외 범위

## Phase 1. PRoot guest 동적 terminal resize

### 목표
- Host PTY master, PRoot tracee fd, guest controlling terminal/foreground process group의 실제 전달 경로를 증명하고 source-level로 수정한다.

### 구현 태스크
- [x] 기존 Samsung 실패 증거와 single PTY/FIFO/PRoot patch 구현을 분석한다.
- [x] `TIOCGWINSZ` enter/exit patch의 syscall ABI·tracee 메모리 경로와 packaged binary를 대조한다. patch가 tracee memory에 `40x120`을 기록해도 BusyBox `stty`가 초기값을 유지함을 재현했다.
- [x] 검증 불충분한 guest FIFO watcher, per-pid terminal fd resize와 ready/ack 환경 변수를 production runtime 경로에서 제거한다.
- [x] native PTY terminal의 public capability를 `INITIAL_SIZE_ONLY`로 고정하고, resize 요청을 `TERMINAL_RESIZE_UNSUPPORTED`로 fail-closed 처리한다.
- [x] Samsung Runtime Probe(2026-08-08)에서 false `DYNAMIC`이 제거되고 initial `stty size=28 96`, explicit unsupported channel/error, terminal close safe exit event, restart/repair와 Host process `STARTED:3`/`STOPPED:3` 균형을 확인했다.
- [x] `setsid`·`TIOCSCTTY`·`tcsetpgrp` native launcher와 Host-private PRoot size state를 Probe 전용으로
  재시험했다. `120×40`/`80×24` 뒤 guest `stty`는 `28 96`, `WINCH` trap은 미수신이어서 source-level
  해결로 승격하지 않았고 experimental code/artifact를 제거했다. 상세: `implement_20260808_141500.md`.
- [ ] PRoot upstream/maintained source-level hook 또는 alternate terminal architecture로 40x120, 80x24, resize storm, rotation, SIGWINCH와 TUI를 해결한다. 현재 release gate는 `BLOCKED`다.

### 자체 테스트
- [x] launcher unit test가 `INITIAL_SIZE_ONLY` terminal의 resize를 `TERMINAL_RESIZE_UNSUPPORTED`로 거부한다.
- [x] Samsung Runtime Probe가 Native PTY initial `stty size=28 96`, explicit unsupported channel/error, terminal close safe exit event와 Host process lifecycle `STARTED:3`/`STOPPED:3`을 확인한다. 이 결과는 dynamic resize·SIGWINCH·orphan matrix를 대체하지 않는다.
- [ ] `stty size`, SIGWINCH, repeated resize와 terminal close 후 orphan 없음의 dynamic matrix는 source-level 해결 뒤에 실행한다.

### 이슈 및 수정
- [x] `GUEST_WINSIZE_NOT_PROPAGATED`: Host/tracee fd는 바뀌지만 BusyBox guest `stty`가 초기 크기를 유지한 기존 증거가 있다.
- [x] false `DYNAMIC` capability: FIFO ready가 실제 guest resize와 동치가 아님을 재현하고 fail-closed contract로 정정했다.
- [ ] source-level dynamic resize solution과 재빌드/실기기 증적 대기

### 완료 조건
- [x] 원인 증거와 안전 fallback을 확정했다. `DYNAMIC` 승격은 별도 capability blocker로 유지한다.
- [x] 가능한 unit/build/Samsung probe 테스트 완료
- [x] Phase 2 진행 가능 — dynamic resize는 product feature가 아니라 open capability blocker로 유지

## Phase 2. 완성형 terminal·session UX

### 목표
- 전용 작업 화면에서 세션·scrollback·입력·종료를 안정적으로 사용한다.

### 구현 태스크
- [x] session header/list/rename/선택·종료를 재사용 `RuntimeHostController` 경계에 구현하고 최대 8개 open session·각 256 KiB scrollback으로 제한한다. terminal 종료 뒤에는 random terminal ID와 numeric exit code만 마지막 종료 요약으로 보관·표시하며, 새 session 또는 runtime stop/reset에서 지운다. 현재 session에는 Ctrl+C, 확인 뒤 SIGTERM, 별도 확인 뒤 SIGKILL을 제공한다. 연결 재개는 새 terminal session을 명시적으로 여는 방식이며 process history를 영구 보관하지 않는다.
- [x] 선택 session만 UI state로 투영하는 bounded output buffer와 scroll/copy, Enter/Tab/Ctrl+C/Esc 입력을 구현한다. Runtime Host에는 raw ANSI bytes를 UI에 노출하지 않는 bounded screen renderer를 추가해 standard SGR colour, cursor 이동, erase, insert/delete, scroll, save/restore cursor와 `1047`/`1049` alternate screen을 처리한다. 화면 크기는 최대 `240 × 120`으로 제한하고 기존 bounded scrollback도 유지한다.
- [ ] 한글 IME·외부 keyboard와 vi/nano/top 대표 흐름을 Samsung에서 검증한다. renderer는 VT 완전 호환 emulator가 아니므로 scroll region, mouse, sixel/graphics 및 검증되지 않은 full-screen app은 완료로 표시하지 않는다.
- [x] 재사용 `RuntimeForegroundProcessListener`가 첫 Runtime host process에서 FGS lease를 얻고 마지막 process 종료에 정확히 한 번 해제한다. nested terminal·command, duplicate close, FGS start rejection host-policy callback은 background module 4/4 unit regression으로 검증했다.
- [ ] 실제 Samsung에서 terminal process 종료 뒤 notification/FGS 제거와 OEM background lifecycle을 수동 검증한다. Doze/reboot/battery restriction은 승인 전 `NOT_RUN`이다.

### 자체 테스트
- [x] Host unit test가 ANSI SGR/OSC redaction, cursor overwrite, clear, alternate screen 복귀, CJK wide glyph과 최대 screen dimension, tab 제거 뒤 raw output 없는 terminal exit summary를 검증한다. Compose/integrated Kotlin compile도 통과했다.
- [x] Samsung Runtime Probe가 actual native PTY에서 terminal close safe exit event와 `STARTED:3`/`STOPPED:3` Host lifecycle 균형을 확인했다. vi/nano/top, 외부 keyboard, FGS/notification cleanup은 이 범위에 포함하지 않는다.
- [ ] 실제 Samsung terminal smoke와 vi/nano/top matrix는 runtime 시작 후 별도로 실행한다.

- [ ] 구현·자체 테스트 완료

## Phase 4. Package·개발 도구·Gateway lifecycle

### 목표
- 승인된 package와 개발 도구, Gateway lifecycle을 사용자 제어·복구 정책으로 제공한다.

### 구현 태스크
- [x] package 검색과 action별 확인 UI를 추가했다. install은 exact allowlist `apk add`만, delete는 별도 removable allowlist만, update는 allowlist의 지정 package만 고정 `apk del`/`apk upgrade` argv로 실행한다. whole-system update와 임의 `apk` subcommand는 제공하지 않는다.
- [x] bundled Alpine `v3.21/aarch64` 공식 `APKINDEX` 확인일 snapshot으로 allowlist별 version·license·download/installed payload·network 필요 여부를 승인 전 UI에 표시한다. catalog는 display-only이며 install policy/argv 생성과 분리하고, dependency/index/cache/filesystem overhead 및 repository 변경은 포함하지 않는다고 명시한다.
- [ ] 실제 Runtime repository preflight에서 읽는 package version·license·전체 dependency/disk size와 network·disk-full·cancel 상태는 아직 검증하지 않았다. snapshot을 live 설치 결과로 표시하지 않으며, 이 matrix는 package mutation을 공개 기능으로 승격하기 전 `NOT_RUN`으로 남긴다.
- [x] Python/Git/SSH/Node exact package profile과 재사용 가능한 fixed-argv first-run smoke workflow를 추가했다. UI는 명시적으로 선택한 profile만 실행하고 성공/실패 상태만 표시하며, Guest stdout/stderr를 상태 화면에 저장하지 않는다. 실제 repository install/first-run은 network 조건에서 별도 검증한다.
- [x] `AlpineLlmBridgeRecoverySupervisor`를 추가해 이미 사용자가 시작한 Gateway만 30초 health poll, 최대 2회, 1~8초 backoff로 제한 복구한다. cold launch 자동 시작, prompt·terminal command 자동 재전송, direct backend 무단 fallback은 금지한다. 명시적 종료는 in-flight health check의 재시작 예약도 취소한다.
- [x] 빠른 채팅 독립성과 prompt/command 자동 재전송 금지를 fake Provider 10턴 회귀로 검증했다. Stop 뒤 새 대화, 실패 뒤 사용자 Retry, model/persona/skill/history 복귀가 request ledger를 중복시키지 않는다.
- [ ] Gateway process crash/runtime restart/stale PID·port cleanup의 Samsung 실기기 matrix는 아직 `NOT_RUN`이다.
