# Phase 1g: second `TIOCGWINSZ` target output lifecycle 분리

작성 일시: `2026-08-09 06:42:00 KST`

## 목적

Relay29는 marker가 요청한 second guest `TIOCGWINSZ`가 enter와 success exit에 도달함을 확인했다. marker가 여전히
응답하지 않는 원인을 다음 안전한 경계로 좁히기 위해, 이 단계는 second get tracee의 첫 write와 exit lifecycle만
고정 enum으로 분리한다.

## 안전 경계

- `Relay30`은 `:alpine-runtime-probe` 전용 disposable PRoot artifact다.
- terminal bytes, command, path, PID, fd number, errno value, credential을 저장하지 않는다.
- stdin replay/retry, polling/FIFO, PID/fd reopen, post-launch signal injection을 추가하지 않는다.
- product Runtime/terminal contract는 바꾸지 않고 `INITIAL_SIZE_ONLY`를 유지한다.

## 구현·검증 체크리스트

- [x] second successful get 이후 target write destination/result와 target exit recorder를 추가했다.
- [x] Probe pack·lock·checksum·parser·intent·boundary test를 연결했다.
- [x] arm64 build, Probe build/unit, boundary test, Samsung seccomp-off control을 수행했다.
- [x] Probe를 제거하고 Samsung에 `dev.alpine.integrated`만 복구했다.
- [x] 결과와 차단 상태를 문서화했다.

## Samsung arm64 결과

처음 Relay30 marker는 `size="$(stty size)"` command substitution을 사용했다. second get target은 stdout write
non-empty와 exit을 보였지만 marker는 응답하지 않았다. 이 stdout은 command-substitution pipe일 수 있으므로, 이
관찰만으로 PTY delivery나 terminal input failure를 주장할 수 없다.

동일한 recorder에서 Probe-only freestanding helper로 marker를 바꾼 control은 second get success exit `1`, target
stdout write non-empty `1`, target exit `1`, 그리고 terminal response `true`를 보였다. helper 결과는
`initial`이었고 dynamic contract는 false였다. 이 run은 lifecycle recorder가 intentionally virtual resize request를
생략한 Relay30 binary이므로 dynamic resize를 검증하지 않는다.

## 판정

- [x] 두 번째 get 직후 guest target의 direct stdout/exit와 terminal delivery가 동작함을 확인했다.
- [x] command-substitution marker의 무응답을 일반적인 PRoot post-get terminal failure로 단정하지 않는다.
- [x] `DYNAMIC` 승격은 하지 않는다. actual virtual/physical resize update, `SIGWINCH`, repeat/storm/rotation,
  TUI/orphan matrix는 아직 미증명이다.
