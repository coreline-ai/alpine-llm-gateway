# implement_20260807_220440.md

작성 일시: `2026-08-07 22:04:40 KST`

이 문서는 Provider 편집 화면의 다음 P1인 **회전·IME·뒤로가기·Activity/process recreation 상태 복구**를 구현하기 위한 작업 계획이다. 기존 필드는 `rememberSaveable`을 사용하지만 새 profile draft ID가 Activity 재생성마다 바뀌어 복원 key가 불안정하고, validation error와 변경사항 이탈 보호가 없으므로 이를 보강한다.

## 개발 목적

- 새 Provider 작성 중 화면 회전·Activity recreation이 발생해도 모든 입력과 UI 상태를 유지한다.
- validation 실패 후 회전해도 오류 안내와 사용자가 수정하던 값을 유지한다.
- 편집 중 시스템 뒤로가기와 상단 뒤로가기가 같은 변경사항 폐기 확인 계약을 사용하게 한다.
- IME가 열린 상태에서도 sticky 저장 action과 편집 필드가 접근 가능하게 한다.
- 실제 저장 전에는 profile store·OAuth token을 변경하지 않고, 사용자 확인 없는 입력 폐기를 방지한다.

## 상태 계약

- 새 draft의 profile ID와 `createdAtMs`는 최초 Activity 생성 시 결정하고 saved instance state로 복구한다.
- 편집 profile은 intent의 profile ID를 정본으로 사용하고 store에서 다시 읽는다.
- 사용자 입력·프로토콜 section 상태·validation error는 Compose saveable state로 복구한다.
- transient model dropdown·IME focus는 재생성 후 닫혀도 되며 입력값에는 영향을 주지 않는다.
- 현재 form을 정규화한 profile이 `initialProfile`과 다르면 dirty 상태다.
- dirty 상태에서 상단/시스템 Back은 폐기 확인을 표시하며, 취소하면 입력을 그대로 유지한다.
- `버리고 나가기`만 Activity를 종료하며 store와 OAuth token은 변경하지 않는다.
- 저장 action은 동기식 store transaction 후 즉시 결과를 반환하므로 pending save/login intent를 재실행하지 않는다.
