# implement_20260809_114746.md

작성 일시: `2026-08-09 11:47:46 KST`

이 문서는 PRoot guest dynamic resize의 source-level 해결 후보를 재시도하기 전에, 현재 pinned
OpenMinis source와 유지보수 중인 Termux fork에 즉시 채택 가능한 `SIGWINCH`/terminal hook이 있는지
read-only로 확인하고 production contract를 정확히 유지하기 위한 조사 기록이다.

## 개발 목적

- 이미 실패한 host signal, PID/fd reopen, polling/FIFO, command replay 우회를 반복하지 않는다.
- pinned OpenMinis source가 원격 `master`와 같은지, Termux maintained fork에 바로 이식 가능한 terminal
  hook이 있는지를 공식 GitHub source/API 기준으로 확인한다.
- source evidence가 없으면 PRoot binary/lock/API를 바꾸지 않고 `INITIAL_SIZE_ONLY`를 유지한다.

## 개발 범위

- OpenMinis `master` HEAD와 runtime lock commit 일치 여부를 read-only 확인한다.
- Termux `master`의 `event_loop()` signal policy와 공개 issue 검색 결과를 확인한다.
- ADR·Host integration 문서에 후보 부재와 다음 acceptance 조건을 기록한다.

## 제외 범위

- 외부 fork를 제품 binary로 교체하거나 unreviewed patch를 ship하지 않는다.
- PRoot source/lock/SBOM/corresponding source, Runtime resize API 또는 Probe 결과를 변경하지 않는다.
- Samsung reboot/Doze, Provider 계정, PRoot dynamic acceptance 재실행은 포함하지 않는다.

## 최종 결과 요약

- OpenMinis remote `master`는 packaged runtime lock의 commit과 같아서 즉시 적용할 upstream 변경이 없었다.
- Termux fork는 더 최근에 유지보수되지만, 확인한 event-loop signal policy와 공개 issue에는 이 프로젝트의
