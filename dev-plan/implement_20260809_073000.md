# Phase 1i: Relay32 virtual winsize repeat·storm fixed-state matrix

작성 일시: `2026-08-09 07:30:00 KST`

## 목적

Relay31은 단일 virtual resize request 뒤 guest helper가 requested large state를 관찰함을 보였다. 이번 단계는
동일한 Probe-only private-memfd source path에서 small (`80×24`) → large (`120×40`) 반복과 bounded 8-step storm을
실행하고, direct guest helper가 raw dimensions 대신 closed fixed state enum으로 각 marker 직전의 결과를 확인한다.

## 안전 경계

- product Runtime/API, PRoot production artifact, resize capability는 변경하지 않는다.
- helper는 `large`/`small`/`initial`/`unexpected`/`unavailable` fixed enum만 출력한다.
- terminal bytes, command, path, PID, fd, errno, credentials, exact dimensions는 report에 저장하지 않는다.
- polling, FIFO, replay/retry, PID/fd reopen, post-launch signal injection을 사용하지 않는다.
- `SIGWINCH`, rotation, TUI, orphan process는 이 단계의 완료 조건이 아니며, 통과해도 product는
  `INITIAL_SIZE_ONLY`를 유지한다.

## Samsung arm64 결과

Relay31 composite artifact를 유지한 Relay32 stress control은 Probe-only helper의 closed state enum으로 다음을
확인했다. raw dimension, command, terminal bytes는 저장하지 않았다.

| 항목 | 결과 | 해석 |
|---|---:|---|
| initial large request + repeat + 8-step storm | `11` private memfd stores | 모든 bounded request가 supervisor에 수용됨 |
| repeat small marker | `MATCHED` | direct helper가 alternate fixed state를 관찰 |
| repeat large marker | `MATCHED` | direct helper가 dynamic fixed state로 복귀 |
| storm final marker | `MATCHED` | 8-step bounded storm 뒤 large state 확인 |
| guest `SIGWINCH` | `0` | no-signal virtual mode의 의도된 결과, signal semantics 미검증 |
| repeat/storm Probe contract | `true` | query-level state transition은 해당 matrix에서 통과 |

이는 PRoot source-level virtual **query** state의 repeat/storm evidence다. physical PTY update, foreground
`SIGWINCH`, rotation, alternate-screen TUI, orphan process는 여전히 미검증이므로 product capability는 승격하지
않으며 `INITIAL_SIZE_ONLY`/`TERMINAL_RESIZE_UNSUPPORTED`를 유지한다.
