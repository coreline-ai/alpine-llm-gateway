# x86_64 Emulator E2E 실행 계획

작성 일시: `2026-08-09 KST`

## 목적

현재 `SKIP_NO_X86_64_EMULATOR`인 x86_64 Runtime E2E gate를 실제 Android x86_64
emulator에서 실행한다. 이 작업은 ARM64 결과나 static artifact 검증으로 x86_64 지원을
추정하지 않고, 별도 일회용 AVD에서 runtime probe의 설치·terminal·restart acceptance를
직접 검증한다.

## 범위와 안전 경계

- Android 35 Google APIs x86_64 system image를 Android SDK에 새로 설치한다.
- 기존 ARM64 AVD와 Samsung 실기기 설정은 변경하지 않는다.
- 새 AVD는 `Alpine_x86_64_API_35` 이름으로 만들며, 이름 충돌 시 덮어쓰지 않는다.
- 실행은 headless·일회용으로 하고, 실계정 Provider·OAuth·API key를 사용하지 않는다.
- gate report에는 ADB serial을 저장하지 않는다(schema 3 유지).
- 실행 뒤 test/probe package를 정리하고 AVD를 종료한다.
- image 다운로드·SDK 변경은 사용자 승인 후에만 실행한다.

## 실행 결과

- [x] Android 35 Google APIs x86_64 system image 설치 승인 획득
- [x] system image 설치 및 SDK package registration 확인
- [x] `Alpine_x86_64_API_35` 일회용 AVD 생성
- [x] headless boot 시도 — **실패**: aarch64 host의 QEMU2 emulator는 x86_64 AVD CPU architecture를 지원하지 않음
- [x] `scripts/runtime/run-x86_64-emulator-gate.sh`를 skip 없이 실행 — 연결된 x86_64 emulator가 없어 `SKIP_NO_X86_64_EMULATOR`
- [x] probe package 미설치 확인·실행 불가 AVD 삭제
- [x] x86 report, release readiness, GOAL audit을 결과에 맞춰 동기화
- [x] Python gate regression·readiness verifier·`git diff --check` 실행

## 성공 기준

1. x86_64 emulator가 `ro.kernel.qemu=1` 및 `x86_64` ABI로 탐지된다.
2. report가 `PASSED`이고 success, health, guest machine, terminal, restart acceptance를 모두 충족한다.
3. report 및 문서에 device serial, credential, prompt, Provider 원문 오류가 없다.
4. 실패하면 실패 이유와 redacted evidence를 남기고 x86 gate를 계속 `BLOCKED`로 유지한다.

## 판정 및 다음 실행 환경

- image 설치와 AVD 생성은 완료했지만, 현재 Apple Silicon/aarch64 host에서 Android Emulator가 x86_64
  guest CPU architecture를 실행하지 못해 ADB-connected x86_64 emulator를 만들 수 없었다.
- 이 결과는 artifact·runtime 코드 결함의 증거가 아니며 x86_64 지원 승격 근거도 아니다. gate는
  `X86_64_EMULATOR_UNAVAILABLE` / `BLOCKED`로 유지한다.
- 다음 실행에는 Intel/AMD x86_64 host의 Android Emulator, 또는 이미 연결된 real x86_64 emulator가 필요하다.
- Provider·OAuth·prompt·credential·device serial은 이 실행에 사용하거나 저장하지 않았다.

## 제외 범위

- Provider 실계정 OAuth/API, x86_64 외 lifecycle/Doze/reboot 검증, 공개 배포 승격은 수행하지 않는다.
- PRoot guest dynamic resize 지원 상태를 이 gate 결과로 변경하지 않는다.
