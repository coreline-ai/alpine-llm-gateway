작성 일시: `2026-08-07 21:48:02 KST`

이 문서는 공통 Chat Feature의 다음 P1인 **답변 생성 중 상태 일관성**을 구현하기 위한 작업 계획이다. 현재 앱은 대화별로 최대 2개의 생성을 병렬 유지하지만, 백그라운드 생성 표시와 대화별 중지 action이 부족하므로 상태 소유권과 사용자 제어를 명시적으로 보강한다.

## 개발 목적

- 답변 생성 중에도 새 대화 생성, history 이동, draft 입력과 모델·스킬 변경을 안전하게 유지한다.
- 현재 대화와 백그라운드 대화의 생성 상태를 구분해 사용자가 어디서 답변이 생성되는지 알 수 있게 한다.
- history에서 생성 중인 특정 대화를 직접 중지할 수 있게 한다.
- 동시에 허용된 생성 수를 모두 사용했을 때 잘못 활성화된 전송 action과 불명확한 무반응을 제거한다.
- 앱 background·회전·process recreation에서 지원 가능한 범위와 중단 복구 규칙을 테스트로 고정한다.

## 상태 계약

- 네트워크 generation Job은 `ChatViewModel`이 conversation ID별로 소유한다.
- 새 대화·history 이동은 다른 대화의 generation을 자동 취소하지 않는다.
- Provider·모델·스킬·persona 변경은 현재 실행 중 응답을 바꾸지 않고 해당 대화의 **다음 요청**부터 적용한다.
- 현재 대화는 하단 Stop, 백그라운드 대화는 history의 대화별 Stop으로 취소한다.
- Activity background와 configuration recreation에서는 ViewModel이 살아 있는 동안 generation을 유지하고 최신 snapshot을 저장한다.
- Android가 process를 종료하면 네트워크 generation을 자동 재실행하지 않으며, 저장된 partial 응답은 `CANCELLED`로 복구한다.
- 동시 생성 제한은 2개이며, 제한 도달 시 새 대화 입력은 허용하되 전송은 비활성화하고 이유를 표시한다.

## 구현 결과

- `ChatUiState`가 전체·백그라운드 generation 수와 새 generation capacity를 명시적으로 제공한다.
- `stopStreaming(conversationId)`가 history에서 선택되지 않은 대화만 중지하며 다른 generation은 유지한다.

- Activity 왕복과 configuration recreation에서는 generation을 유지하며, process load에서는 partial text를 보존한 `CANCELLED` 상태로 복구하고 요청을 자동 재실행하지 않는다.
