# implement_20260807_212729.md

작성 일시: `2026-08-07 21:27:29 KST`

이 문서는 남은 P1 중 Provider 저장·인증 흐름과 안전한 오류 상태를 먼저 완성하고, 다음 작업자가 회귀 테스트와 후속 범위를 이어갈 수 있도록 구현 범위를 고정하기 위한 작업 문서다.

## 개발 목적

- Provider 편집 화면의 단일 `저장` 동작을 `저장하고 로그인`과 `나중에 로그인`으로 분리한다.
- 편집 Activity 결과를 Provider 목록 Activity가 받아 저장된 profile을 즉시 인증할 수 있게 한다.
- OAuth 예외 원문을 노출하지 않고 안정적인 오류 코드·사용자 안내·다음 action을 해당 Provider card에 표시한다.
- 인증 중 진행 상태와 사용자 취소를 해당 card에서 처리하고 다른 profile의 충돌 action을 차단한다.

## 개발 범위

- Provider 저장 action 계약과 안전한 인증 오류 모델
- `ProviderEditActivity` 결과 contract
- `ProviderProfilesActivity` 저장 후 인증·취소 orchestration
- Provider 편집 bottom action과 profile card 상태 UI
- 순수 단위 테스트, Compose instrumentation test, Android build·lint, Samsung 실기기 회귀
- 상위 개발 계획의 중복 상태와 이번 구현 결과 갱신

## 제외 범위

- 실제 Provider 계정 발급·운영 OAuth E2E는 수행하지 않는다.
- Provider endpoint·scope·모델 catalog 계약은 변경하지 않는다.
- 공통 채팅 history, process death 복구와 Alpine 터미널 기능은 이번 구현에 포함하지 않는다.
- 공개 배포 license·corresponding source·Play Console gate는 변경하지 않는다.
- 인증 실패 시 Provider 원문 message, endpoint, response body를 UI·로그·테스트 증거에 저장하지 않는다.

## 구현 결과

- Provider 편집 결과는 profile ID와 login 요청 boolean만 전달하며 credential·endpoint를 전달하지 않는다.
- `ProviderPostSaveLoginPolicy`가 저장만 하기, 미인증 profile 로그인, 이미 인증된 profile no-op을 결정론적으로 구분한다.
- `ProviderConnectionIssue`는 private constructor와 `OAuthFailureKind` allowlist mapping으로만 생성되어 예외 원문을 보존하지 않는다.
- 인증 중 card는 progress와 `로그인 취소`를 표시하고, 다른 profile의 연결·편집·overflow action은 비활성화한다.
- Samsung 저장만 하기 수동 검증 후 생성한 테스트 profile을 삭제해 기기 상태를 원복했다.
