# implement_20260808_234657.md

작성 일시: `2026-08-08 23:46:57 KST`

이 문서는 Android PRoot terminal의 동적 resize를 `INITIAL_SIZE_ONLY`에서 실제 `DYNAMIC`으로 승격할 수
있는지 검증하고, 증명 가능한 source-level 해법만 production에 반영하기 위한 작업 문서다.

## 개발 목적

- Host `TIOCSWINSZ` 뒤 PRoot guest의 interactive input이 멈추는 원인을 source-level로 분리한다.
- `SIGWINCH → fixed printf → stty` 이후에도 command input이 재개되는 terminal session 경로를 만든다.
- Samsung arm64에서 repeat/storm/rotation/TUI/terminal-close matrix가 통과한 경우에만 product capability를
  `DYNAMIC`으로 승격한다.

## 개발 범위

- pinned OpenMinis PRoot source의 disposable, Probe-only patch와 host-only reproducer 분석
- Android native PTY / PRoot process lifecycle의 resize 순서와 signal mask·ptrace stop 상태 검토
- product 코드와 Probe artifact의 hard boundary 유지
- deterministic unit/boundary/build 검증, 연결된 Samsung arm64 실제 Probe 검증
- 결과에 따른 production capability·ADR·readiness 갱신

## 제외 범위

- `/proc` PID lookup, master/slave fd 재개방, guest FIFO/polling, payload parsing/logging
- host foreground-group blind broadcast 또는 all-tracee signal injection
- resize 문제를 우회하는 screen recreation, input replay, shell command injection
- x86_64, Provider OAuth, package/workspace, release signing·legal 범위

- [x] signal을 guest에 전달하지 않는 control과 foreground tracee control의 결과 차이를 source artifact로 고정한다.

### 자체 테스트

- [x] disposable patch apply smoke와 arm64 build가 통과한다.
- [x] existing Runtime/API/boundary unit tests가 통과한다.

### 이슈 및 수정

- [x] `relay24` memfd write, no-write control, no-request control 모두 같은 post-arm input 중단을 보였다.
- [x] resize API 호출 자체를 생략한 skip-resize control도 primary-tracee foreground topology에서는 동일하게
  marker/helper/follow-up input이 미응답이었다. 따라서 memfd·socket·`SIGWINCH`가 단독 원인이 아니다.
- [x] primary-tracee foreground 이동을 끈 session topology control도 같은 input failure를 보였다. 이 topology는
  후보 해법이 아니다.
- [x] 기본(unpatched) PRoot와 relay24의 TIOCGWINSZ 분리 control을 추가했다. read를 전부 생략하면 여러 독립
  fixed input batch가 통과하지만, initial `stty size` 뒤 별도 input batch는 재개되지 않았다. seccomp-off와
  Android ioctl seccomp filter를 완전히 제거한 relay25 control도 결과를 바꾸지 못했다. 따라서 root-cause
  working hypothesis는 PRoot terminal의 post-`TIOCGWINSZ` lifecycle이며, 아직 source-level root cause로
  확정하지 않는다.
- [x] 동일 Samsung native host-PTY control에 `TIOCGWINSZ → separate input` 단계를 추가했고 통과했다.
  Android PTY/host control 일반 동작은 blocker가 아니며 PRoot tracee event-loop/source path를 다음 조사 범위로
  확정한다.
- [x] stdin/stdout/stderr slave descriptor를 `dup2`로 canonicalize하는 Probe-only topology도 시도했으나,
  Samsung에서 PRoot prompt 이전부터 입력/출력이 성립하지 않았다. shared-fd topology는 후보에서 제외한다.
- [x] `relay26`은 successful guest `TIOCGWINSZ` exit와 그 뒤의 guest `read(2)` lifecycle만 fixed enum으로
  기록했다. 기본 seccomp run의 `read(2)` enter 0회는 일반 `read`가 PRoot seccomp fast path에서 recorder를
  통과하지 않을 수 있어 단독 증거가 아니다. Samsung seccomp-off control에서는 `TIOCGWINSZ` exit 3회 뒤
  `read_enter`/`read_exit_nonempty`를 각 1회 관찰했지만 fixed marker/helper/follow-up은 계속 미응답이었다.
  따라서 원인을 단일 internal branch로 단정하거나 product resize를 승격하지 않는다.
- [x] `relay27` seccomp-off parent/child control은 첫 `TIOCGWINSZ` child exit, parent wait exit, parent
  non-empty read를 각 1회 기록했지만 acknowledgement·marker·helper/follow-up output은 여전히 없었다.
  따라서 post-ioctl read 부재 가설은 제거하되, shell parser·PRoot syscall interleaving·PTY output 중 정확한
  internal root cause를 확정하지 않는다.

## 잔여 리스크 / 후속 과제

- 2026-08-09 Samsung arm64에서 host-only PTY control은 `TIOCSWINSZ → SIGWINCH → later input`을 통과했지만,
  relay24 및 base-PRoot terminal은 guest `TIOCGWINSZ` 뒤 별도 input batch를 재개하지 못했다. TIOCGWINSZ를
  전부 생략한 base control은 여러 batch를 통과했고 seccomp-off와 source-level ioctl-filter bypass는 failure를
  바꾸지 못했다.
- 따라서 현재 disposable supervisor+PRoot job-control topology와 PRoot terminal ioctl lifecycle은 solution
  후보가 아니며 Phase 3 acceptance matrix는 시작 조건을 충족하지 못했다. product는 `INITIAL_SIZE_ONLY`를 유지한다.
- Relay28 fixed-printf control은 첫 successful guest `TIOCGWINSZ` 뒤 단순 input/output은 응답함을 확인했다.
  그러므로 위의 post-ioctl input failure는 첫 ioctl만으로 일반화하지 않는다. Relay29/Relay30은 second get
  success와 direct-helper terminal delivery도 확인했다. command-substitution marker의 무응답은 일반 terminal
  failure 증거가 아니며, 세부 결과는 `implement_20260809_064200.md`에 기록한다.
- 다음 후보는 session supervisor를 production 경로에 이식하지 않고 PRoot upstream/maintained terminal
  job-control hook 또는 PRoot를 통과하지 않는 대체 backend를 확보한 뒤, **resize 이전 baseline input**과
  `SIGWINCH → fixed printf → stty` 단일 회귀를 별도로 통과시키는 것이다. PID lookup·blind signal dispatch·input
  replay는 금지한다.
