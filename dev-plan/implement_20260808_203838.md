# PRoot resize 실패 경로 제거 및 source-to-binary 동기화

작성 일시: `2026-08-08 20:38 KST`

## 목적

현재 제품은 PRoot guest 동적 resize를 지원하지 않고
`INITIAL_SIZE_ONLY`로 fail-closed 처리한다. 그러나 packaged `libproot.so`에는 이전의
`PROOT_WINSIZE_FILE` 기반 `TIOCGWINSZ` 메모리 override patch가 아직 포함되어 있다.
Samsung에서 guest `stty` 및 foreground `SIGWINCH`를 갱신하지 못했고, 제품 Runtime은
해당 environment를 제공하지 않는다.

이 작업은 실패한 state-file/FIFO 계열 resize 시도를 제품 native binary·source bundle·SBOM에서
제거한다. 이는 dynamic resize를 완료로 주장하는 작업이 아니다. 다음 source-level 해결은
Host master와 guest tty의 동일성, `TIOCSWINSZ`, foreground `SIGWINCH` 및 `TIOCGWINSZ`의
연결을 별도 재현 binary로 증명한 뒤에만 추진한다.

## 범위 및 안전 조건

- [x] `scripts/runtime/patches/proot-android-winsize.patch`와 build pipeline에서 unverified
  `PROOT_WINSIZE_FILE` override를 제거한다.
- [x] arm64-v8a와 x86_64 PRoot를 pinned OpenMinis revision에서 다시 빌드하고,
  packaged binary·runtime lock·SBOM·source offer·source bundle verifier를 함께 갱신한다.
- [x] public Runtime contract는 계속 `INITIAL_SIZE_ONLY`이며 `DYNAMIC`을 노출하지 않는다.
- [x] product에 FIFO, polling, `/proc/<pid>/fd` 재개방 또는 raw terminal diagnostic을 넣지 않는다.
- [x] 기존 사용자 변경은 reset/clean/stash/revert하지 않으며 commit/push하지 않는다.

- arm64-v8a PRoot: `5d2959c3…b5bc29`, `279,144` bytes, machine `183`, 모든 `PT_LOAD` alignment `16,384`.
- x86_64 PRoot: `f0356742…13fbfd`, `292,584` bytes, machine `62`, 모든 `PT_LOAD` alignment `16,384`.
- 둘 다 OpenMinis `8cf13e997cdc9472997aae19df8050c073c9a86c`의 local PRoot patch 없는 build다.
- OSS native source bundle은 `native_components_complete=true`로 검증됐지만 Alpine rootfs package
  source mirror를 포함하지 않으므로 `runtime_source_complete=false` 및 공개 배포 `NO-GO`를 유지한다.
- Samsung Android 16 arm64 Probe는 새 arm64 PRoot에서 `runtime_version=...unpatched1`,
  `healthy=true`, initial `stty size=28 96`, `INITIAL_SIZE_ONLY`,
  `TERMINAL_RESIZE_UNSUPPORTED`, safe terminal close와 restart/repair healthy를 확인했다.
  Probe는 제거했고 최종 `dev.alpine.integrated` APK를 cold start했다.
- Samsung 계측은 Dream overlay가 Compose hierarchy를 가린 첫 시도를 분리했다. 화면을 깨운 clean run은
  OAuth core `3/3`, Provider `12/12`, integrated `10/10` PASS였고 최종 Activity가 foreground임을 확인했다.

## 완료 기준

1. shipped PRoot binary와 lock/SBOM/source-offer가 동일한 unpatched source build를 가리킨다.
2. legacy override string과 dead path가 production source/binary metadata에 남지 않는다.
3. guest dynamic resize는 계속 `BLOCKED`이며, `INITIAL_SIZE_ONLY` 증거가 유지된다.
4. 실제 Provider E2E, Doze/reboot, Play, 법무·라이선스 최종 결정, x86_64 emulator E2E는
   외부 조건이므로 `NOT_RUN`/`BLOCKED`로 유지한다.
